# 게임 평가와 개선 로드맵 / Game Assessment & Improvement Roadmap

[← README](../README.md) · [English project guide](README.en.md)

> **평가 기준:** 2026-09-24 기준 main 브랜치의 코드·문서·공개 웹 빌드를 검토한 데스크 리뷰입니다. 처음부터 끝까지의 밸런스 플레이테스트나 다양한 기기 성능 측정은 포함하지 않았습니다.
>
> **Scope:** This is a desk review of the main branch, documentation, and public web build as of 2026-09-24. It is not a full balance playthrough or device-performance certification.

## 총평 / Verdict

**8.0 / 10 — 규모와 정체성이 분명한, 매우 야심 찬 브라우저 샌드박스입니다.**

*Ashfall Chronicles*의 가장 큰 장점은 단순히 기능이 많은 데 있지 않습니다. 채굴·제작·전투·탐험·생활·자동화가 모두 “다음 장을 열기 위한 준비”라는 하나의 진행 흐름에 붙어 있습니다. 18개 장의 스토리 구조는 자유도가 높은 샌드박스가 방향을 잃기 쉬운 문제를 잘 보완합니다. 픽셀 아트, 장 도입 카드, 보스 연출, 사운드와 대사까지 갖춘 점도 브라우저 기반 개인 프로젝트로서는 인상적입니다.

The primary risk is not lack of content; it is **discoverability and maintainability**. A new player has many systems to understand, while the codebase centralizes large amounts of game data and behavior in a few very large files. The web build also being ahead of the downloadable build is accurately disclosed, but can still confuse players and complicate bug reports.

## 잘되는 점 / What is already working

### 1. 샌드박스의 자유와 이야기의 방향이 충돌하지 않습니다

플레이어는 땅을 파고, 어디에 기지를 지을지 정하고, 무기·스킬·생산선을 고를 수 있습니다. 동시에 장별 목표와 보스가 “다음에 무엇을 할지”를 제시합니다. 이 결합은 오픈월드 피로를 줄이는 강한 설계입니다.

### 2. 시스템이 독립 기능으로 끝나지 않습니다

농사·낚시·요리·펫·마을·기계는 각각 장식이 아니라 탐험·전투·보급·회복에 연결됩니다. 특히 자동화는 후반으로 갈수록 수집 노동을 줄여 더 어려운 지역과 보스에 집중하게 만드는 역할을 할 수 있습니다.

### 3. 제작 규율이 보입니다

`story-and-sessions.md`는 장 확장 시 빠뜨리기 쉬운 데이터 표, 세이브를 깨는 상수, 생성물 경로, 애셋 검증 방식을 구체적으로 기록합니다. 이는 대형 콘텐츠 게임에서 실제로 가치가 큰 자산입니다.

## 주의할 점 / Main risks

### P0 — 빌드 채널과 저장 호환성

현재 웹은 v1.1 개발판이고 다운로드는 v1.0.5입니다. README에 이를 명시했지만, 사용자는 “다운로드”를 안정판의 동의어로, “웹 플레이”를 체험판의 동의어로 받아들이기 쉽습니다.

**권장:** 홈·다운로드·게임 타이틀 화면에 동일한 버전 채널 문구를 사용하고, “웹 저장은 다운로드판으로 자동 이전되지 않음”을 다운로드 직전과 저장 내보내기 화면에 한 번 더 표시하세요. 버그 제보 템플릿에는 build/version/플랫폼/저장 이전 여부를 받으세요.

### P1 — 첫 30분의 학습 곡선

시작부터 가방, 능력, 일지, 제작, 의뢰, 마을, 기계, 재련, 지도 등 다수의 UI가 준비되어 있습니다. 기능이 많다는 장점이 초반에는 판단 부담으로 바뀔 수 있습니다.

**권장:** 첫 세션에서는 장 목표에 필요한 패널만 단계적으로 강조하고, 다음 행동을 한 문장으로 제시하는 “현재 할 일” 카드와 첫 사망·첫 막힘에 대한 회복 팁을 넣으세요. 자동화는 첫 전력원·첫 생산선·첫 병목을 미니 퀘스트로 나누는 편이 좋습니다.

### P1 — 운영 기준 문서와 기록 문서의 분리

`docs/`에는 현재 기준, 계획 프롬프트, 변경 내역, 자산 작업 기록이 함께 있습니다. 자료 자체는 훌륭하지만 새 기여자는 무엇이 최신 규칙인지 판단하기 어렵습니다.

**권장:** 이 문서 인덱스를 유지하고, 새 변경은 “현재 기준 / 기록” 중 어디에 들어가는지 PR 설명에 명시하세요. 최신 플레이어용 문서는 README와 영어 가이드에만 중복 없이 집약합니다.

### P2 — 대형 파일의 안전한 분리

`data.js`(콘텐츠), `game.js`(루프·렌더·상호작용), `world.js`(생성·지형)가 매우 큽니다. 당장 모듈화 자체가 목표가 되면 위험하지만, 새 세션을 추가할 때 충돌·회귀 검증 비용이 커질 가능성이 높습니다.

**권장:** 먼저 읽기 전용 데이터부터 세션/챕터/적/아이템 단위 파일로 분리하고, 기존 전역 이름을 유지하는 조립 단계로 호환성을 확보하세요. 이후 작은 고정 시드 스모크 테스트와 세이브 불러오기 테스트를 자동화합니다.

### P2 — 영어 경로의 범위 설정

영어로 “소개·시작·조작·저장·기여 진입”을 제공하는 것은 즉시 효과가 큽니다. 모든 서사·아이템·UI를 성급히 이중화하면 갱신 불일치가 생길 수 있습니다.

**권장:** 공개 README, 릴리스 노트 요약, 설정·저장 경고부터 영어화합니다. 실제 게임의 현지화는 용어집, 키 기반 문자열, 한 세션 단위 검수라는 별도 마일스톤으로 다루세요.

## 제안 로드맵 / Suggested roadmap

| 우선순위 | 다음 결과물 | 성공 기준 |
|---|---|---|
| P0 | 버전 채널·저장 호환 경고 통일 | 웹/다운로드/게임 내에서 같은 버전과 호환 문구를 읽을 수 있음 |
| P1 | 첫 30분 온보딩 | 새 저장에서 다음 행동을 묻는 순간이 줄고, 첫 제작·보스·저장 내보내기를 자연스럽게 경험함 |
| P1 | 문서 기준선 | README → 문서 인덱스 → 현재 규약의 3단계로 최신 정보를 찾을 수 있음 |
| P2 | 회귀 스모크 테스트 | 고정 시드 생성, 새 저장, 기존 저장 로드, 핵심 UI 열기 검증 |
| P2 | 데이터 분리의 첫 단계 | 새 장의 콘텐츠 표를 독립 파일에서 추가하고 기존 세이브가 로드됨 |
| P3 | 현지화 기반 | 문자열 키·용어집·영어 UI의 한 세션 검수 경로가 준비됨 |

## 다음 릴리스에 권하는 최소 범위 / Recommended next-release minimum

1. 웹/다운로드 버전 차이와 저장 이전 방법을 모든 진입 지점에 통일해 표시합니다.
2. 첫 장에 “일지 확인 → 도구 제작 → 첫 목표”를 보여 주는 짧은 안내를 추가합니다.
3. 신규 유저용 영어 안내와 이 문서 인덱스를 최신 상태로 유지합니다.
4. 기존 저장을 하나 이상 포함한 스모크 체크리스트를 릴리스 절차에 넣습니다.

이 네 가지는 새 콘텐츠를 줄이지 않으면서도 게임을 더 믿고 시작하고, 더 안전하게 고칠 수 있게 만드는 투자입니다.
