# 시스템 요구사항

브라우저판은 웹(`/play`)이나 내려받은 `index.html`에서 실행할 수 있고, 별도로 같은 `play/` 파일을 Electron으로 포장한 앱판도 있습니다.
브라우저판의 기존 수치는 1~4절, Electron 앱판의 실측과 별도 사양은 5절을 보세요.

브라우저판의 기존 수치는 3절의 측정이 근거입니다. Electron 앱판의 측정 조건과 한계는 5절에 따로 적었습니다.

## 1. 브라우저로 열 때

### 1-1. 브라우저 (여기가 진짜 문턱입니다)

| | 최소 | 권장 |
|---|---|---|
| **Chrome · Edge** | 99 이상 (2022-03) | 111 이상 (2023-03) |
| **Firefox** | 97 이상 (2022-02) | 113 이상 (2023-05) |
| **Safari** | 16 이상 (2022-09) | 16.2 이상 (2022-12) |
| **그래픽 가속** | **켜져 있어야 합니다** | 〃 |

- **최소선을 정한 것은 캔버스의 `roundRect`** 입니다. 몹 이름표를 그릴 때 쓰는데 두 곳이
  대비 없이 부르고 있어서(`game.js` 5824·5856), 없는 브라우저에서는 그 자리에서 멈춥니다.
- **권장선을 정한 것은 CSS 의 `color-mix()`** 입니다(테두리 광택 8곳). 없어도 **게임은
  그대로 돕니다** — 창 테두리의 은은한 빛만 안 납니다.
- **그래픽 가속이 꺼져 있으면 못 씁니다.** 브라우저 판에서 "왜 느리냐"의 대부분이
  이것입니다. Chrome·Edge 는 `설정 → 시스템 → 가능한 경우 그래픽 가속 사용`,
  Firefox 는 `설정 → 성능 → 권장 성능 설정 사용`. 실측으로 가속이 없으면 1080p 가
  **16fps** 입니다.

## 2. 안 되는 것 · 주의할 것

| | |
|---|---|
| **휴대폰 · 태블릿** | 터치 조작을 지원합니다. 휴대폰은 가로 화면을 권장하며, 작은 화면에서는 일부 HUD가 간소화됩니다 |
| **게임패드** | 안 받습니다 |
| **사생활 보호 모드(시크릿)** | **창을 닫으면 저장이 사라집니다.** 저장은 그 브라우저 안(IndexedDB)에만 있습니다 |
| **브라우저를 바꾸면** | 이어지지 않습니다. Chrome 에서 하던 것을 Safari 에서 열면 새 여정입니다 |
| **"방문 기록·사이트 데이터 삭제"** | 저장이 같이 지워집니다 |
| **탭을 많이 띄워 두면** | 메모리가 모자랄 때 브라우저가 **이 탭부터** 버립니다(400 MB 짜리라서). 돌아오면 다시 읽습니다 |

## 3. 이 숫자가 어디서 나왔나

재는 조건이 **GPU 없는 컨테이너의 소프트웨어 래스터라이저**라 프레임 시간은 실제 기기보다
나쁜 쪽입니다 — 사양을 낮춰 잡지 않으려고 그대로 씁니다.

| 재는 것 | 값 | 어떻게 쟀나 |
|---|---|---|
| 첫 방문 전송량 | **7.5 MB** / 요청 453개 | 응답 `content-length` 합산 |
| └ 갈래별 | PNG 364개 4.05 MB · MP3 74개 2.02 MB · JS 13개 1.35 MB · CSS 0.05 MB | 〃 |
| 여는 시간 | 100/25/10/4 Mbps → **3.9 / 5.0 / 8.9 / 20.5초**, 재방문 **약 1초** | CDP 로 망을 조여서 측정 |
| 그림이 **메모리에서** | **376 MB** (디코딩 362장) | `naturalWidth×naturalHeight×4` 합산 |
| └ 그중 보스 시트 다섯 | **164 MB** (복원자 11328×1056 한 장이 45.6 MB) | 〃 |
| JS 힙 | 14~19 MB | `performance.memory` |
| 세계 배열 | 5.8 MB (4200×480 × 3벌 + 빛 버퍼) | 배열 길이 합산 |
| 세계 생성(로딩) | **4.8 ~ 5.9초** | `new World(seed).generate()` 세 번 |
| 프레임 시간 p50 | 720p **29.4 ms** · 1080p **63.3 ms** · 1440p **108.8 ms** | 180프레임 |
| 몹 40마리를 더 부른 뒤 | 29.4 → **31.4 ms** (720p) | 〃 |
| 저장 | 갓 시작 **955 KB** · 최악 **2,037 KB** | 저장 글자열 길이(압축 전) |
| 저장 한도 | IndexedDB 수백 MB (`navigator.storage.estimate()`) · localStorage 로 떨어지면 약 4 MB | 〃 |
| 디스크 | 게임 폴더 61 MB — 소리 53.6 MB(43개) · 그림 4.2 MB(PNG 375장) | `du` |

### 숫자에서 사양이 나오는 방식

- **메모리 4 GB** — PNG 는 디스크에서 4.2 MB 지만 화면에 올리려면 **RGBA 로 펴야** 하고,
  그게 376 MB 입니다(보스 시트 하나가 11328×1056). 거기에 JS 힙·세계 배열·캔버스 버퍼가
  붙어 탭 하나가 약 400 MB 입니다.
- **그래픽에 "가속 여부"만 요구** — 셰이더도 WebGL 도 3D 도 안 씁니다. Canvas 2D 의
  `drawImage` 뿐이라 요구하는 것은 성능이 아니라 **가속이 켜져 있는가**입니다.
- **몹을 마흔 더 불러도 2 ms 밖에 안 늘었습니다** — 병목이 개체 수가 아니라 **채우는
  픽셀 수**라는 뜻이고(1440p 가 1080p 의 1.7배), 그래서 CPU 보다 **해상도**가 사양을 가릅니다.
  창을 줄이거나 설정의 「시야 범위」를 **올리면**(좁게 보임) 가벼워집니다.
- **4코어 권장은 코어를 써서가 아닙니다.** 게임은 싱글 스레드고, 줄여야 하는 것은 로딩
  5초라 사실상 단일 코어 성능의 표시입니다.
- **첫 방문 7.5 MB 뿐인 까닭** — 53.6 MB 인 배경음을 부팅에 안 받기 때문입니다.
  그림은 PNG 가 잘 눌려서(4.2 MB) 전부 받아도 가볍습니다.

## 5. Electron 앱으로 열 때 · Steam 포장의 바탕

Electron 앱판은 `play/`를 Chromium과 함께 포장해 별도 창에서 실행합니다. 시스템에 브라우저를 설치할 필요가 없고, 브라우저판과 파일은 같지만 저장 공간은 분리됩니다. 이 앱 포장은 향후 Steam 배포에도 쓸 수 있는 바탕입니다.

| 포장 방식 | 런타임 용량 | 영향 |
|---|---|---|
| **Electron** | +180~200 MB | 브라우저를 같이 들고 다녀 어디서나 같은 그림이 나온다 |
| Tauri / WebView2 | +10 MB | 용량은 줄지만 **OS 의 웹뷰 판에 따라 그림·소리가 갈린다** |

### Electron 앱 실측

| 항목 | 측정 결과 |
|---|---|
| 장치 | ASUS BR1100FKA · Windows 11 64-bit · Intel Celeron N4500 (2코어/2스레드, 1.1 GHz 기준) · 메모리 3.75 GB · Intel UHD Graphics |
| 앱 | 저장소의 Windows x64 포장본 · Electron 44.5.1 · 창 1280×760 (게임 뷰포트 1264×705) |
| 첫 화면 로드 | **26.1초** (`PerformanceNavigationTiming` 문서 로드 시간; 타이틀/저장 슬롯 화면 표시 확인) |
| 앱 메모리 | **526 MiB 작업 집합** · **347 MiB 비공유 메모리** (Electron 브라우저·렌더러·GPU·네트워크·오디오 5개 프로세스 합계) |
| 안정 프레임률 | 미측정 — 이 장치에서 월드 진입 후 장시간 플레이 FPS는 검증하지 않음 |

### v1.1.5 다시 잼 — 같은 조건에서 v1.1.4 와 견줌 (2026-10-22)

실제 기기가 아니라 **가상 화면(Xvfb) · GPU 없음** 컨테이너에서 같은 포장 방식(Electron 44.5.1 · 창 1280×760 · 소형 세계)으로 두 판을 차례로 띄웠습니다
(`tests/out/_appmeasure.mjs` — 앱 프로세스 일곱 개의 `smaps_rollup` 합). 절대값보다 **두 판의 차이**를 보는 측정입니다.

| 항목 | v1.1.4 | v1.1.5 | 왜 |
|---|---|---|---|
| 비공유 메모리 · 타이틀 | 744 MB | **439 MB** | 보스 시트(펴면 338 MB)를 처음에 안 읽는다 · 쓰지 않던 장 그림 63 MB 를 안 편다 |
| 비공유 메모리 · 플레이 | 972 MB | **536 MB** | 〃 |
| 비공유 메모리 · 보스 하나와 싸울 때 | 980 MB | **680 MB** | 그 보스 시트만 읽고, 2분 안 그리면 놓는다 |
| RSS 합(공유 포함) · 플레이 | 1,501 MB | **1,050 MB** | |
| 타이틀까지(디스크 캐시가 데워진 뒤) | 2.4초 | **1.4초** | 부팅에 읽는 그림이 줄었다 |
| 새 여정(소형 세계 생성) | 3.1초 | 3.4초 | 같은 생성 — 오차 범위 |
| 세이브 본문 한 번 | 634 KB | **82 KB** | 바탕 + 바뀐 청크(docs/code-history.md#h205) |

프레임 시간은 이 환경에서 화면 갱신(약 30 Hz)에 묶여 두 판 모두 p50 33 ms 로 나와 비교에 쓰지 않았습니다.
실제 기기(Celeron N4500)에서의 v1.1.4 타이틀 26.1초 · 작업 집합 526 MiB 는 위 표의 차이만큼 줄 것으로 보지만, 그 기기에서 다시 재기 전까지는 v1.1.4 실측으로 둡니다.

이 측정은 실제 저사양 장치의 포장 앱 실행값이지 여러 기기에서 확인한 인증 최소선은 아닙니다. 앱은 타이틀/저장 슬롯까지 열렸지만 첫 로드가 느렸고, 월드 진입 후 안정적인 게임 플레이 FPS는 확인하지 못했습니다. 따라서 아래 최소선은 **앱을 열 수 있었던 실측 하한**이고, 전체 플레이 성능의 최소선은 추가 기기 시험 전까지 잠정값입니다.

### 최소선을 올린 까닭 — Celeron N4500 에서 2fps (2026-10-22 사용자 실측)

같은 기기(위 표의 Celeron N4500)에서 월드에 들어가면 **가장 낮은 화질에서도 약 2fps** 였다. 헤드리스로 단계를 끄며 재 보니 JS 는 한 프레임 6 ms 남짓이고
나머지는 **화면 칠하기**였다(1920×1080 · 소프트웨어 칠하기: 11.4fps, 몸 그리기 · 빛 판 · 타일 · 하늘이 고르게 나눠 먹음). 그래서 v1.1.5 의 절약 화질은
화소 수 상한(1024×576 상당)을 둔다 — 같은 조건 11.4 → **35.8fps**(3.1배) · 1366×768 은 46fps. 자동 화질은 GPU 없이 칠하는 환경(WebGL 렌더러가 SwiftShader 따위)을 알아보면 절약으로 떨어진다.
N4500 은 이 기기 비율(11.4 : 2 ≈ 5.7배 느림)로 치면 고친 뒤에도 약 6fps 라 최소선 밖으로 둔다. 새 최소선(i5-8250U · 4코어 8스레드)은
N4500 보다 단일 코어 약 1.5배 · 다중 코어 약 3배라 절약 화질 1080p 에서 30fps 안팎을 노린다 — **추정**이고, 그 급 기기에서 다시 재면 이 줄을 실측으로 바꾼다.
