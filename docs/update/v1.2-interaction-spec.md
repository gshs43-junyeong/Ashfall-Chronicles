# Ashfall Chronicles --- v1.2 Interaction Specification

> **목적:** v1.2에서 추가·개선할 상호작용을 하나의 구현 기준으로
> 정리한다.
>
> **핵심 방향:** 새로운 콘텐츠를 무작정 늘리는 것이 아니라, **플레이어의
> 행동이 기존 월드의 다른 시스템을 움직이게 만드는 것**을 우선한다.
>
> **중요:** 아래 목록은 현재까지 공유된 Ashfall의 구조를 기준으로 만든
> 설계 카탈로그다. 실제 코드에 존재하지 않는 시스템은 그대로 구현
> 대상으로 확정하지 말고, `조건부` 항목으로 취급한다.

------------------------------------------------------------------------

## 0. v1.2의 핵심 원칙

Ashfall의 v1.2 상호작용은 다음 구조를 목표로 한다.

``` text
Player Action
    ↓
World State Change
    ↓
NPC / Economy / Ecology / Town / Quest Reaction
    ↓
Secondary Consequence
    ↓
New Player Decision
```

단순히:

``` text
버튼 클릭 → 숫자 +1
```

이 되는 기능은 v1.2의 핵심 상호작용으로 취급하지 않는다.

### 상호작용의 최소 조건

각 상호작용은 가능하면 다음 5개 중 4개 이상을 만족한다.

-   [ ] 플레이어가 직접 발견할 수 있다.
-   [ ] 한 번 이상 다시 사용할 이유가 있다.
-   [ ] 다른 시스템에 영향을 준다.
-   [ ] 예상과 다른 2차 결과가 발생할 수 있다.
-   [ ] 결과가 월드에서 관찰 가능하다.

# 1. Player → World

## IW-001. 오브젝트 파괴 → 월드 변화

플레이어가 파괴 가능한 오브젝트를 제거하면 해당 위치의 월드 상태가
바뀐다.

**예시** - 막혀 있던 길이 열린다. - 건물 내부로 진입할 수 있다. - 자원
공급원이 사라진다. - NPC 이동 경로가 바뀐다.

**Priority:** MUST

------------------------------------------------------------------------

## IW-002. 오브젝트 제거 → NPC 경로 변화

플레이어가 장애물을 제거하면 NPC의 이동 가능 경로가 달라진다.

**Priority:** SHOULD

------------------------------------------------------------------------

## IW-003. 오브젝트 배치 → 이동 경로 변화

플레이어가 설치한 구조물이 통행 가능 공간을 바꾼다.

**Priority:** MUST

------------------------------------------------------------------------

## IW-004. 길 차단 → 우회

플레이어가 특정 통로를 막으면 NPC 또는 다른 월드 객체가 다른 경로를
선택한다.

**Priority:** SHOULD

------------------------------------------------------------------------

## IW-005. 임시 구조물 → 임시 경로 생성

일시적으로 설치한 구조물이 새로운 이동 루트를 만든다.

**Priority:** SHOULD

------------------------------------------------------------------------

## IW-006. 환경 오브젝트 조사 → 정보 획득

특정 오브젝트를 조사하면 단순 설명뿐 아니라 다른 시스템을 이해할 수 있는
단서를 제공한다.

**Priority:** SHOULD

------------------------------------------------------------------------

## IW-007. 같은 장소 재방문 → 상태 변화 확인

플레이어가 같은 장소를 다시 방문했을 때 이전 행동의 결과가 남아 있어야
한다.

**Priority:** MUST

------------------------------------------------------------------------

## IW-008. 플레이어 행동 → 지역 위험도 변화

특정 행동이 해당 지역의 위험도 또는 활동량에 영향을 준다.

**Priority:** SHOULD

------------------------------------------------------------------------

## IW-009. 플레이어 행동 → 자원 분포 변화

플레이어가 자원을 과도하게 사용하면 해당 지역의 자원 상태가 달라진다.

**Priority:** SHOULD

------------------------------------------------------------------------

## IW-010. 플레이어 행동 → 다른 자원 접근 가능

하나의 자원을 소비하거나 제거함으로써 다른 자원에 접근할 수 있다.

**Priority:** SHOULD

------------------------------------------------------------------------

# 2. World → Player

## WP-001. 월드 상태에 따른 새로운 접근 경로

월드 상태가 바뀌면 기존에 접근할 수 없었던 장소가 열린다.

**Priority:** MUST

------------------------------------------------------------------------

## WP-002. 월드 상태에 따른 접근 제한

반대로 플레이어의 행동으로 기존 경로가 제한될 수 있다.

**Priority:** SHOULD

------------------------------------------------------------------------

## WP-003. 지역 상태 변화 → 시각적 피드백

월드의 상태 변화는 플레이어가 화면에서 확인할 수 있어야 한다.

**Priority:** MUST

------------------------------------------------------------------------

## WP-004. 월드 상태 변화 → NPC 대사 변화

월드가 바뀌면 관련 NPC의 대사나 반응이 달라진다.

**Priority:** MUST

------------------------------------------------------------------------

## WP-005. 월드 상태 변화 → 상점/거래 변화

지역의 상태가 경제 시스템에 영향을 준다.

**Priority:** SHOULD

------------------------------------------------------------------------

## WP-006. 월드 상태 변화 → 이벤트 발생 조건 변화

월드 상태가 이후 이벤트의 조건을 변경한다.

**Priority:** SHOULD

------------------------------------------------------------------------

# 3. Player → NPC

## PN-001. NPC에게 특정 자원 제공

플레이어가 NPC에게 필요한 자원을 제공하면 NPC의 상태가 변화한다.

**Priority:** MUST

------------------------------------------------------------------------

## PN-002. NPC에게 불필요한 자원 제공

모든 아이템이 항상 동일한 가치로 받아들여지지 않는다.

**Priority:** SHOULD

------------------------------------------------------------------------

## PN-003. NPC 요구 → 플레이어 행동 변화

NPC의 상태가 플레이어에게 특정 행동의 동기를 제공한다.

**Priority:** SHOULD

------------------------------------------------------------------------

## PN-004. 플레이어의 반복 행동 → NPC 반응 변화

동일한 행동을 반복하면 NPC가 이를 인식하거나 반응한다.

**Priority:** SHOULD

------------------------------------------------------------------------

## PN-005. 플레이어 선택 → NPC 관계 변화

선택에 따라 NPC와의 관계 또는 협력 가능성이 달라진다.

**Priority:** MUST

------------------------------------------------------------------------

## PN-006. 플레이어 행동 → NPC 신뢰 변화

대화 선택뿐 아니라 실제 플레이 행동도 NPC의 신뢰도에 영향을 줄 수 있다.

**Priority:** SHOULD

------------------------------------------------------------------------

## PN-007. NPC에게 역할 부여

플레이어의 마을 운영 방식에 따라 NPC의 역할이 바뀐다.

**Priority:** MUST

------------------------------------------------------------------------

## PN-008. NPC 역할 변경 → 마을 기능 변화

NPC의 역할이 바뀌면 해당 NPC가 담당하는 기능도 달라진다.

**Priority:** MUST

------------------------------------------------------------------------

## PN-009. NPC 상태 악화 → 역할 상실

NPC가 특정 조건을 충족하지 못하면 담당 기능이 약화되거나 중단된다.

**Priority:** SHOULD

------------------------------------------------------------------------

## PN-010. NPC 상태 회복 → 기능 복구

플레이어가 문제를 해결하면 NPC의 기능을 다시 사용할 수 있다.

**Priority:** SHOULD

------------------------------------------------------------------------

## PN-011. NPC 이동 조건 변화

NPC의 위치가 고정되어 있더라도, 이동이 필요한 상태를 시스템적으로 표현할
수 있어야 한다.

**Priority:** SHOULD

------------------------------------------------------------------------

## PN-012. NPC 이탈

특정 조건에서 NPC가 마을을 떠날 수 있다.

**Priority:** EXPERIMENTAL

------------------------------------------------------------------------

## PN-013. NPC 복귀

이탈 원인이 해결되면 NPC가 다시 돌아올 가능성을 제공한다.

**Priority:** EXPERIMENTAL

------------------------------------------------------------------------

## PN-014. NPC의 플레이어 행동 기억

이전에 발생한 중요한 행동을 이후 반응에 반영한다.

**Priority:** SHOULD

------------------------------------------------------------------------

# 4. NPC ↔ NPC

## NN-001. NPC 간 거래

NPC끼리의 관계가 마을의 자원 흐름에 영향을 준다.

**Priority:** SHOULD

------------------------------------------------------------------------

## NN-002. NPC 간 협력

서로 다른 역할의 NPC가 함께 존재할 때 추가적인 기능이 활성화될 수 있다.

**Priority:** SHOULD

------------------------------------------------------------------------

## NN-003. NPC 역할 충돌

특정 역할 조합이 다른 기능을 약화시키거나 선택지를 만든다.

**Priority:** EXPERIMENTAL

------------------------------------------------------------------------

## NN-004. NPC 관계 변화 → 마을 기능 변화

NPC 관계가 단순 대사 변화에 그치지 않고 실제 기능에 영향을 줄 수 있다.

**Priority:** EXPERIMENTAL

------------------------------------------------------------------------

## NN-005. NPC 부재 → 다른 NPC 역할 대체

한 NPC가 기능을 수행하지 못하면 다른 NPC가 일부 기능을 대신할 수 있다.

**Priority:** SHOULD

------------------------------------------------------------------------

## NN-006. 역할 대체 → 효율 차이

대체 NPC는 원래 담당자와 동일한 결과를 내지 않을 수 있다.

**Priority:** SHOULD

------------------------------------------------------------------------

# 5. Town Building

## TB-001. 건물 위치 → 기능 변화

같은 건물이라도 어디에 배치하느냐에 따라 기능이 달라진다.

**Priority:** MUST

------------------------------------------------------------------------

## TB-002. 건물 간 인접 효과

건물의 위치 관계가 다른 건물의 효과에 영향을 준다.

**Priority:** MUST

------------------------------------------------------------------------

## TB-003. 건물 접근성

건물의 위치가 NPC 또는 플레이어의 접근성을 변화시킨다.

**Priority:** SHOULD

------------------------------------------------------------------------

## TB-004. 건물 배치 → NPC 이동 경로 변화

건물 배치가 NPC의 이동 패턴에 영향을 준다.

**Priority:** MUST

------------------------------------------------------------------------

## TB-005. 건물 철거 → 기존 기능 상실

철거는 단순히 건설 비용을 되돌리는 것이 아니라 실제 기능을 제거한다.

**Priority:** MUST

------------------------------------------------------------------------

## TB-006. 건물 철거 → 다른 기능 활성화

건물을 없애 새로운 공간이나 경로를 확보할 수 있다.

**Priority:** SHOULD

------------------------------------------------------------------------

## TB-007. 건물 재배치

이미 설치한 시설의 위치를 바꾸는 것이 가능하다.

**Priority:** SHOULD

------------------------------------------------------------------------

## TB-008. 건물 조합

특정 시설 조합이 새로운 기능을 만든다.

**Priority:** SHOULD

------------------------------------------------------------------------

## TB-009. 건물 과밀

시설을 지나치게 밀집시키면 일부 기능이 약화될 수 있다.

**Priority:** EXPERIMENTAL

------------------------------------------------------------------------

## TB-010. 빈 공간의 가치

건물이 없는 공간 자체가 이동, 방어, NPC 행동 등의 측면에서 의미를
갖는다.

**Priority:** SHOULD

------------------------------------------------------------------------

## TB-011. 마을 구조 → 방어 구조 변화

건물 배치가 마을의 방어 효율에 영향을 준다.

**Priority:** SHOULD

------------------------------------------------------------------------

## TB-012. 마을 구조 → 자원 운송 변화

시설 간 거리가 자원 이동이나 생산 효율에 영향을 줄 수 있다.

**Priority:** EXPERIMENTAL

------------------------------------------------------------------------

## TB-013. 시설의 상태 변화

시설이 정상 / 사용 불가 / 복구 중 등의 상태를 가질 수 있다.

**Priority:** MUST

------------------------------------------------------------------------

## TB-014. 시설 복구

손상되거나 비활성화된 시설을 다시 사용할 수 있다.

**Priority:** MUST

------------------------------------------------------------------------

# 11. Combat / Threat → World

## PS-005. 세션 전환 상태 유지

Session 1 → Session 2 전환에서 필요한 월드 상태가 정확히 전달된다.

**Priority:** MUST

------------------------------------------------------------------------

# 26. Session 1 → Session 2

## S12-001. 플레이어의 주요 선택 전달

Session 1의 중요한 선택이 Session 2의 일부 상태에 영향을 준다.

**Priority:** MUST

------------------------------------------------------------------------

## S12-002. 발견한 정보 전달

Session 1에서 얻은 정보가 이후 플레이에서 의미를 가진다.

**Priority:** SHOULD

------------------------------------------------------------------------

## S12-003. 마을 상태 전달

Session 1의 결과가 Session 2의 마을 상태와 연결될 수 있다.

**Priority:** SHOULD

------------------------------------------------------------------------

## S12-004. NPC 상태 전달

중요 NPC의 상태 또는 관계가 이어진다.

**Priority:** SHOULD

------------------------------------------------------------------------

## S12-005. 단순 리셋 방지

Session이 바뀌었다고 해서 모든 시스템 상태가 의미 없이 초기화되지
않는다.

**Priority:** MUST

------------------------------------------------------------------------

# 27. High-Value Interactions

다음은 v1.2에서 특히 **"이 게임이 단순 RPG가 아니구나"**라는 인상을 만들
가능성이 높은 항목이다.

### HV-001. 문제 해결 → 다른 문제 발생

플레이어가 문제를 해결하면 시스템이 새로운 문제를 만든다.

### HV-002. 마을 구조 → NPC 행동

건축이 단순 스탯 업그레이드가 아니라 NPC 행동을 변화시킨다.

### HV-003. NPC 부재 → 마을 기능 변화

NPC가 단순 장식물이 아니다.

### HV-004. 건물 철거 → 새로운 전략

건설뿐 아니라 철거에도 전략적 의미가 있다.

### HV-005. 플레이어 행동 → 월드의 기억

월드가 플레이어의 과거 행동을 기억한다.

### HV-006. 선택 → 간접적 결과

선택 직후의 보상보다 몇 단계 뒤의 결과가 중요하다.

### HV-007. 습격 → 복구 우선순위

습격이 단순 전투 이벤트가 아니라 마을 운영 문제를 만든다.

### HV-008. 지역 안정화 → 압력 이동

한 지역의 문제를 해결하면 다른 지역의 문제가 증가할 수 있다.

### HV-009. 같은 아이템 → 서로 다른 시스템

플레이어가 자원을 어디에 사용할지 결정한다.

### HV-010. 시스템 무시 가능성

플레이어가 특정 시스템을 사용하지 않아도 다른 방식으로 진행할 수 있다.

------------------------------------------------------------------------

# 28. v1.2에서 특히 피해야 할 가짜 상호작용

## FAKE-001. 숫자만 바뀌는 상호작용

``` text
상호작용
→ +10 경험치
```

다른 시스템에 영향을 주지 않으면 우선순위를 낮춘다.

------------------------------------------------------------------------

## FAKE-002. 대사만 바뀌는 선택

``` text
A 선택
→ NPC 대사 A

B 선택
→ NPC 대사 B
```

월드 상태가 같다면 강한 상호작용으로 보지 않는다.

------------------------------------------------------------------------

## FAKE-003. 건물 외형만 변경

건물 외형만 달라지고 기능이 동일하다면 유연한 건축으로 간주하지 않는다.

------------------------------------------------------------------------

## FAKE-004. 고정 NPC + 고정 역할

NPC의 위치와 역할이 항상 동일하고 플레이어 행동에 반응하지 않는다면
시스템적 NPC로 보기 어렵다.

------------------------------------------------------------------------

## FAKE-005. 랜덤 이벤트 남발

단순 랜덤 발생을 상호작용으로 간주하지 않는다.

좋은 랜덤 이벤트:

``` text
월드 상태
→ 조건 계산
→ 사건 발생
→ 플레이어 대응
→ 상태 변화
```

나쁜 랜덤 이벤트:

``` text
랜덤
→ 사건 발생
→ 보상 지급
```

------------------------------------------------------------------------

## FAKE-006. 퀘스트 수만 증가

퀘스트를 많이 추가하는 것 자체는 v1.2의 시스템 상호작용 목표가 아니다.

------------------------------------------------------------------------

# 29. Interaction Priority

## P0 --- 반드시 구현

-   월드 변경의 지속성
-   건물 배치 → NPC/경로 변화
-   건물 철거 → 기능 변화
-   NPC 역할 → 마을 기능 변화
-   아이템 → 복수 시스템
-   선택 → 시스템 상태 변화
-   습격 → 마을 상태 변화
-   습격 → 복구
-   Session 상태 전달
-   플레이어 행동 → 최소 하나 이상의 2차 시스템 반응

## P1 --- 강력 권장

-   NPC 행동 변화
-   NPC 역할 대체
-   경제와 자원 연결
-   지역 위험도
-   지역별 상태
-   시간 기반 NPC 변화
-   퀘스트 우회 해결
-   지역 안정화 → 다른 지역 변화
-   NPC의 행동 기억
-   시스템 간 연쇄 반응

## P2 --- 실험적

-   NPC 이탈/복귀
-   복잡한 경제
-   자원 생태계
-   위험 압력의 지역 이동
-   NPC 간 관계 시뮬레이션
-   복잡한 시장 가격
-   창발적 시스템 조합

------------------------------------------------------------------------

# 30. 구현 순서

## Phase 1 --- State Foundation

먼저 다음 상태를 명확하게 만든다.

``` text
WorldState
TownState
NPCState
BuildingState
ResourceState
QuestState
ChoiceState
RaidState
SessionState
```

각 상태는 가능하면 서로 직접적인 하드코딩보다 **공유된 상태 데이터**를
통해 연결한다.

------------------------------------------------------------------------

## Phase 2 --- Core Reactions

먼저 구현할 연쇄:

``` text
Building → NPC
Building → Path
NPC → Town
Resource → Crafting
Crafting → Building
Town → Raid
Raid → Building
Choice → NPC
Choice → World
```

------------------------------------------------------------------------

## Phase 3 --- Secondary Reactions

그 다음:

``` text
World → NPC
NPC → Economy
Economy → Town
Combat/Threat → World
World → Quest
Time → NPC
Time → World
```

------------------------------------------------------------------------

## Phase 4 --- Emergent Systems

마지막으로:

``` text
Problem A 해결
→ System B 변화
→ Problem C 발생
→ 새로운 플레이어 선택
```

형태의 연쇄를 추가한다.

# 31. Interaction Acceptance Test

새로운 상호작용을 추가할 때 다음 질문을 모두 통과해야 한다.

### Test 1 --- 발견 가능성

플레이어가 결과를 알아차릴 수 있는가?

### Test 2 --- 재사용성

한 번 보고 끝나는 기능이 아닌가?

### Test 3 --- 연결성

다른 시스템 하나 이상과 연결되는가?

### Test 4 --- 선택성

플레이어가 무엇을 할지 결정할 여지가 있는가?

### Test 5 --- 결과성

플레이어 행동에 실제 결과가 존재하는가?

### Test 6 --- 지속성

중요한 결과가 월드에 남는가?

### Test 7 --- 비선형성

A를 했다고 반드시 A라는 보상만 나오는 구조는 아닌가?

### Test 8 --- 대체 가능성

플레이어가 다른 방법으로 같은 문제에 접근할 수 있는가?

### Test 9 --- 관찰 가능성

월드, NPC, 아이템, 시설 등의 변화로 결과를 확인할 수 있는가?

### Test 10 --- 시스템 가치

이 기능을 제거했을 때 게임플레이가 실제로 달라지는가?

**10개 중 7개 미만이면 v1.2 핵심 상호작용으로 넣지 않는 것을 권장한다.**

------------------------------------------------------------------------

# 32. 최종 목표

v1.2의 목표는 상호작용 개수를 늘리는 것이 아니다.

최종적으로 플레이어가 다음과 같은 사고를 하게 만드는 것이 목표다.

``` text
"이걸 하면 뭐가 바뀌지?"
```

그리고 게임이:

``` text
플레이어 행동
↓
월드 변화
↓
NPC 반응
↓
자원/경제 변화
↓
새로운 문제
↓
플레이어의 재판단
```

으로 답해야 한다.

즉,

> **Ashfall의 핵심 상호작용은 "상호작용할 수 있는 오브젝트가 많다"가
> 아니라, "하나의 행동이 다른 시스템의 상태를 바꾼다"에 있다.**

v1.2에서는 새로운 맵이나 수백 개의 퀘스트를 추가하는 것보다 **현재 월드
구조를 최대한 활용해 시스템 간 연결 밀도를 높이는 것**을 우선한다.

------------------------------------------------------------------------

## Implementation Rule

> **Do not add an interaction merely because it is possible. Add it when
> the interaction creates a meaningful new decision.**
