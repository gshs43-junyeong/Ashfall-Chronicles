## 1. 무엇이 문제였나 — 눈이 아니라 숫자로

"움직임이 둔하다"를 판정하려고 스프라이트 시트의 프레임끼리 실제 픽셀 차이를 쟀습니다.
지표는 **두 프레임을 겹쳤을 때 달라지는 픽셀이 불투명 면적의 몇 %인가**이고,
경험적으로 **5% 아래면 사람 눈에 정지로 읽힙니다.**

측정 도구를 리포지토리에 넣어 뒀습니다.

```bash
python3 tools/framediff.py
```

## 2. 코드로 고친 것 (이번 커밋)

그림을 다시 그리는 게 근본 해결이고, 아래는 **그때까지의 가림막**입니다.

### 2-1. 근접 몹이 공격 그림을 처음으로 보여 줍니다 ★ 영향 가장 큼

`game.js:enemyFrame()` 이 공격 포즈를 `atkCd > 1.4` 로 판정하고 있었습니다.
그런데 **`atkCd` 는 화살(archer)·마법(caster)을 쏘는 놈만 설정합니다**
(`entity.js` 745 / 767행 부근). 근접 몹은 `hitCd = 0.7` 짜리 접촉 피해로 때리므로
`atkCd` 가 **영원히 0** 이었고, 결과적으로 **프레임 4(공격 그림)를 단 한 번도
보여 주지 않았습니다.** 79종 중 대부분이 여기 해당합니다.

- `Enemy` 에 `atkPose` 타이머 추가, 매 프레임 감쇠
- 접촉 피해가 실제로 들어간 순간 `atkPose = 0.22`
- 원거리·마법도 발사 순간 `atkPose = 0.26` (기존엔 1.4 아래로 떨어질 때까지 0.4~1.4초를
  공격 자세로 굳어 있었습니다 — 이제 짧고 또렷합니다)
- `enemyFrame()` 은 `atkCd` 대신 `atkPose` 를 봅니다

**검증**: 슬라임을 소환해 접촉시키니 `atkPose 0.22` → `enemyFrame` 이 `4` 반환. 이전엔 불가능.

### 2-2. 그림이 안 움직이는 개체를 렌더러가 흔들어 줍니다

`ENEMIES` 에 **`stiff`** 표시를 넣었습니다(위 측정에서 5% 안팎인 것만). 값은 흔드는 세기.

```
ballast_form 1.15 · lost_miner 0.8 · lavaslug 0.9 · riveter 0.9 · crystalcrab 0.9
scrapcrawler 0.7 · glow_snail 1.3 · arctic_hare 1.2 · ash_vole 1.1 · jungle_frog 0.7
first_keeper 1 (보스)
```

`game.js:drawEnemy()` 가 이 표시를 보고

- **걸을 때**: 걸음 프레임과 같은 박자(7Hz)로 위아래 튀기 + 진행 방향으로 기울이기
- **서 있을 때**: idle 박자(2.4Hz)로 숨쉬기

**검증**: 일곱 장이 전부 같던 `glow_snail` 이 두 프레임 사이에 8,795픽셀 차이를 냅니다
(이전 0). 예외 없이 돕니다.

### 2-3. 보스 페이즈 전환이 눈에 보입니다

보스 시트는 페이즈마다 idle 두 장뿐이고, `void_king`(1.5%) · `bone_lord`(3.3%) ·
`shaft_maw`(6.6%) 는 그림만으로 페이즈가 바뀐 걸 알 수 없었습니다.
`entity.js` 의 페이즈 계산부에 **전환 순간 감지**를 넣었습니다.

- 파티클 26개 버스트 + 화면 흔들림 11 + `chapter` 효과음
- `phaseT` 0.7초 동안 금빛 섬광 (`drawEnemyOverlay`)

**검증**: `void_king` 체력을 50%로 낮추니 `phase 0→1`, 파티클 +26, 흔들림 11.

### 2-4. 곁들여 정리한 것

손그림 몹 위에 얹는 것들(피격 섬광 · 체력 막대 · 페이즈 섬광)을
**`drawEnemyOverlay()` 로 분리**했습니다. 흔들림 경로와 일반 경로가 같은 것을
그려야 해서입니다. 동작은 그대로입니다.

## 3. ★ 병합 시 충돌 지점

v1.1 작업분이 같은 파일을 건드렸을 가능성이 높습니다. **충돌 나면 아래 기준으로 푸세요.**

| 파일 | 위치 | 변경 내용 | 병합 방침 |
|---|---|---|---|
| `js/data.js` | `const ENEMIES` 앞 주석 | stiff 설명 + 측정값 | 그대로 유지 |
| `js/data.js` | 11개 개체의 `ai: '...'` 뒤 | `stiff: N` 삽입 | **v1.1이 그 개체를 손댔어도 `stiff` 는 살리세요** |
| `js/entity.js` | `Enemy` 생성자 | `atkPose` · `lastPhase` 필드 | 양쪽 다 채택 |
| `js/entity.js` | `Enemy.update` 첫 줄 | `this.atkPose -= dt;` | 양쪽 다 채택 |
| `js/entity.js` | 접촉 피해 블록 | `atkPose = 0.22` | 양쪽 다 채택 |
| `js/entity.js` | archer/caster 발사부 | `atkPose = 0.26` | 양쪽 다 채택 |
| `js/entity.js` | `this.phase = hpr < 0.33 …` | 전환 감지 블록 | 양쪽 다 채택 |
| `js/game.js` | `enemyFrame()` | `atkCd > 1.4` → `atkPose > 0` | **이쪽을 채택** |
| `js/game.js` | `drawEnemy()` 앞 | `drawEnemyOverlay()` 신규 | 양쪽 다 채택 |
| `js/game.js` | `drawEnemy()` 손그림 분기 | stiff 흔들림 경로 | 양쪽 다 채택 |

**v1.1에서 새로 추가한 몹·보스가 있다면** `python3 tools/framediff.py` 의 `CHARS` /
`BOSSES` 배열에 이름을 넣고 돌려 보세요. 5% 아래가 나오면 `stiff` 를 붙이면 됩니다.

**캐시 무효화 값(`game/index.html` 의 `?v=183`)은 일부러 안 올렸습니다.**
v1.1 전체를 합칠 때 한 번만 올리세요 (12곳).

## 4. 남은 것 — 그림으로만 되는 일

코드는 흔들어 줄 수는 있어도 **없는 자세를 만들어 내지는 못합니다.**
`assets/_gen/pixlib.js` 로 굽는 방식은 그대로 쓰면 됩니다.

### 4-1. 걸음 프레임 (우선순위 높음)

**`ballast_form` (평형추 · spd 54 · 세션2 후반 몹)**
통짜 원통 몸통에 짧은 다리 두 개. 지금은 다섯 장이 사실상 같은 그림.
→ **뒤뚱거림**으로 갑니다. `move1` = 몸통 3° 왼쪽 기울임, 왼다리 뻗고 오른다리 접기,
몸통 1px 올림. `move2` = 좌우 반전. 원통이라 다리보다 **기울임이 걸음을 읽게** 합니다.

**`arctic_hare` (눈산토끼 · spd 70 · critter)**
지금 `move1 == move2 == idle1`. 토끼는 걷지 않고 **뜁니다.**
→ `move1` = 웅크림(몸 낮추고 귀 뒤로 눕히고 뒷다리 접기), `move2` = 도약
(몸 늘이고 앞다리 뻗고 귀 뒤로 흘림, 2~3px 띄우기). 두 장이면 충분합니다.

**`ash_vole` (잿들쥐 · spd 85)**
idle 은 62.6%로 잘 움직이는데 걸음이 8.0%. → 걸음에 **종종걸음**을 넣으세요.
다리 두 쌍 교차 + 몸통 앞뒤 신축 1px + 꼬리 반대 위상으로 흔들기.

**`glow_snail` (빛달팽이 · spd 24 · 일곱 장 전부 동일)** — 가장 심함
달팽이는 몸을 늘였다 줄이며 나아갑니다.
→ `idle1/idle2` = 껍질 발광 밝기 두 단계 + 더듬이 한쪽 기울임.
→ `move1` = 몸 앞으로 늘이고 껍질 뒤에 남김, `move2` = 껍질 당겨 붙이고 몸 수축.
→ `atk` 는 dmg 0인 순한 동물이니 `idle1` 재사용해도 무방합니다.

### 4-2. idle 프레임 (`idle1 == move1` 끊기)

**`riveter`** — idle 두 장이 완전 동일. `idle2` 에 머리 1px 내리기 + 어깨 처짐만
넣으면 됩니다. 걸음(44.6%)은 이미 건강합니다.

**`crystalcrab`** — 걸음(58%)은 훌륭한데 `idle1 == move1`.
`idle1/idle2` 를 **쉬는 자세**로 새로 그리세요(다리 낮추고 집게 접기). 그러면
걷기 시작이 또렷해집니다.

**`lavaslug`** — 위와 같은 문제. `idle` 을 웅크린 자세로.

**`scrapcrawler` · `jungle_frog`** — idle 두 장만 갈라 주면 끝. 걸음/도약은 건강합니다.

### 4-3. 보스

**`first_keeper` — 숨쉬기 (0.2% / 0.1%)**
`p1i2` 에 가슴판 1px 올리기 + 눈 발광 한 단계 + 가슴 마름모 문양 밝히기.
p2도 같은 요령. **여섯 장 중 세 장만 손보면 됩니다.**

**`void_king`(1.5%) · `bone_lord`(3.3%) · `shaft_maw`(6.6%) · `pursuer` p1→p2(8.1%)
— 페이즈 구분**
코드 연출로 전환 순간은 알 수 있게 했지만, **전환 후의 모습이 같은 건 그대로**입니다.
페이즈마다 실루엣이 달라져야 합니다 — 갑옷 파편 떨어져 나가기, 균열과 발광 번지기,
자세 낮추기, 팔·가시 벌리기 중 하나를 **누적**으로.
기준: **p1→p2 가 20% 이상** 나오면 눈에 띕니다.

### 4-4. 보스 이동·공격 시트 (가장 큼, 별도 작업으로)

지금 보스 시트는 **페이즈별 idle 두 장, 총 6장뿐**입니다. 이동도 공격도 idle 로 때웁니다.
프레임을 늘리려면 `manifest.json` 의 `bosses.frames` 배열과 `count`,
`game.js:enemyFrame()` 의 보스 분기를 함께 고쳐야 합니다.
**보스 20종 × 추가 프레임이라 분량이 커서, 이번 범위에서는 뺐습니다.**

## 5. 그림을 다시 그린 뒤 할 일

1. `python3 tools/framediff.py` 다시 돌리기
2. 해당 개체 수치가 **10% 이상**으로 올라갔으면 `js/data.js` 에서 그 개체의
   **`stiff` 를 떼세요.** 그림이 움직이는데 코드까지 흔들면 이중으로 흔들립니다.
3. `first_keeper` 는 `stiff: 1,` 을 지우면 됩니다.
4. 전부 뗀 뒤에도 `drawEnemy` 의 흔들림 경로는 남겨 두세요 — 앞으로 추가될 몹에 씁니다.
