**핵심 사실 넷 — 작업 전에 반드시 인지할 것**

1. **`site/play/` 는 빌드 산출물이다.** `game/` 의 복사본이고 `.gitignore` 되어 있다. 게임을 고칠 때는 **언제나 `game/` 만** 고친다. `site/play/` 를 고치면 다음 빌드에 날아간다.
2. **월드 생성은 결정론적이다** (`util.js` mulberry32, 시드 문자열). 같은 시드 = 같은 세계. 지형 생성 코드를 바꾸면 **기존 세이브의 세계와 어긋나지 않는지** 반드시 따져야 한다. 세이브는 타일 배열 전체를 RLE로 들고 있으므로 이미 생성된 세계는 안전하지만, **새로 생성되는 구조물의 좌표 규칙을 바꾸면 신규 세계에만 적용된다**.
3. **세계 크기는 `WW=4200 × WH=480` 타일**(`world.js:5-6`). `SURF_BASE=70`, `DEEP_Y=280`, `HELL_Y=390`, `SKY_Y=40`. 세이브 로더가 `d.world.ww !== WW` 이면 로드를 거부한다(`game.js:2052`). **WW/WH 를 바꾸면 모든 기존 세이브가 죽는다 — 절대 바꾸지 말 것.**
4. **런타임은 결정론적이지 않다** (`Math.random()` 72곳). 새 기능에서 월드 생성에 쓰는 난수는 반드시 `rng`(시드 RNG)를, 연출·전투에 쓰는 난수는 `Math.random()` 을 쓴다. 섞지 말 것.

**이미 끝난 것 (다시 하지 말 것)**

- 조작 안내줄(`#hint`) 삭제 — 커밋 `0a228a5` 에서 앱·웹 양쪽에서 제거 완료. `SET_DEFAULT.hint`, 설정의 "조작 안내줄" 항목, `applySettings`/`bindSettings`/`syncSettings` 의 관련 줄까지 전부 정리됨. **요청 목록에 있지만 이미 완료 상태다.**

## 1. 작업 순서

의존 관계가 있으므로 이 순서를 지킬 것. 각 단계 끝에 브라우저로 실제 실행해 확인한다.

| 단계 | 내용 | 이유 |
|---|---|---|
| A | 마이그레이션 골격 + 세이브 내보내기/불러오기 | **가장 먼저.** 이후 모든 변경이 세이브 호환성을 건드린다. 여기가 없으면 테스트마다 진행이 날아간다 |
| B | 버그·밸런스 (황금 상자, 캠프 NPC) | 작고 독립적. 빨리 끝내고 넘어간다 |
| C | 타일 아트 (물·폭포·마그마 애니메이션, 마그마 분포) | 렌더러에 프레임 개념을 넣는 작업. 이후 아트 작업이 여기 얹힌다 |
| D | 오브젝트 아트 (분수·전신주·풍차) | C의 프레임 개념을 재사용 |
| E | 물 물리 (수영·산소·공기 봉지) | F의 새 지역(바다)이 이것 위에 선다 |
| F | 세션 3 지역 생성 (바다·산맥·글리치 섬) | E 필요 |
| G | 세션 3 스토리 3장 + 비밀 NPC | F 필요 |
| H | 폭탄 + 화약 | F 필요(화약이 세션 3 산출) |
| I | 마을 확장 (레벨 4·상점·농경지) · 공장 레벨 4 · 펫 레벨 | 서로 독립. 병렬 가능 |
| J | 업적 | 다른 시스템의 카운터를 참조하므로 마지막 |
| K | 사이트 반영 + 릴리스 | 아래 §4 를 그대로 따를 것 |

### B-1. 황금 상자 동굴 밸런스

**현재 상태 — 문제의 정확한 위치**
- `world.js:2033 buildCaverns(rng)`:
  - `cy = rng.int(this.surface[cx] + 22, min(WH - 20, HELL_Y - 8))` → **지표에서 22칸(약 480px) 아래면 생성 가능.** 이게 "너무 얕다"의 원인.
  - `if (cy < 90) continue;` 라는 하한이 있지만 지표가 70 근처라 사실상 거의 안 걸린다.
  - `rng.chance(0.45)` 로 황금 상자(`tier: 6`) + 가시 함정 1개.
- `entity.js:93 rollChest(tier, rng, source)`:
  - `tier >= 6` 이면 `gold = true`.
  - `gold` 일 때: 장비 **2~3개**를 `luckTier = 9` 로 굴린다(최고 등급 확률이 `0.8 + 9*0.4 = 4.4` 로 5배 이상 뛴다).
  - `if (!(gold || rng.chance(0.72))) continue;` — **`gold` 면 모든 재료가 100% 확정**으로 최대 수량까지 나온다.
  - 금 원석 `rng.int(10, 18)` (일반 상자는 1~4).
  - 전리품 표는 `CHEST_LOOT[5]` (최상위: `staff_soul`, `chest_mythril`, `pick_soul`, `hell_ore`, `soul_shard`, `void_frag`).

**할 일**
- [ ] **깊이 제약**: `cy` 하한을 `DEEP_Y`(280) 근처로 올린다. 예: `rng.int(Math.max(this.surface[cx] + 60, DEEP_Y - 30), min(WH - 20, HELL_Y - 8))`. 정확한 값은 실제로 파 내려가 보고 조정할 것.
- [ ] **깊이에 따른 보상 등급**: `tier: 6` 고정을 버리고 `cy` 로 등급을 정한다. 예 — `DEEP_Y` 위쪽이면 4, `DEEP_Y`~`HELL_Y` 면 5, 그 아래면 6. `caverns` 배열에 등급을 함께 저장해 세이브에도 남길 것.
- [ ] **`gold` 특혜 축소** (`rollChest`):
  - `luckTier` 를 9 → 3~4로 낮춘다.
  - 재료 100% 확정을 없앤다: `rng.chance(0.85)` 정도로.

- [ ] **접근 난이도 상향**: 함정을 1개에서 3~4개로 늘리고, 황금 상자 방 입구를 `T.BEDROCK` 이 아닌 단단한 광석으로 한 겹 막아 곡괭이 등급을 요구하게 한다.

### C. 물 · 폭포 · 마그마 타일 애니메이션 + 마그마 분포

**현재 상태 — 여기가 이 항목의 핵심 난점**
- `tileart.js` 는 타일마다 **변형 4개**(`TileArt.V = 4`)를 아틀라스에 미리 그려 둔다.
- 렌더러(`game.js:2300`)가 변형을 **위치 해시로** 고른다: `const v = (tileHash(tx, ty) * VA) | 0;`
- **즉 현재 타일에는 시간 개념이 전혀 없다.** 애니메이션을 넣으려면 렌더러에 프레임 선택을 추가해야 한다.
- 물·폭포는 손그림 스프라이트를 쓴다: `TILE_SPRITE = { water: T.WATER, falls: T.FALLS, ... }` (`data.js:252`). `TileArt.applySprite(id, img)` 가 **한 장을 변형 4칸 전부에 복사**한다.
- 마그마(`T.LAVA`)는 절차 생성이다: `ART[T.LAVA] = { k: 'lava', c: '#e0561c' }`.
- **`assets/tile/` 에 `water.png` / `falls.png` 파일이 실제로는 없다** — 매니페스트에는 등록되어 있으나 파일 부재로 절차 생성(`k:'water'`)으로 떨어지고 있다. 새로 그려 넣을 좋은 기회다.

**할 일 — 권장 설계**
- [ ] `ART` 항목에 `fr`(프레임 수)과 `fps` 를 추가한다. 예: `ART[T.WATER] = { k:'water', c:'#2f6f9f', a:1, fr:3, fps:4 }`, `ART[T.FALLS] = { ..., fr:2, fps:10 }`(빠르게), `ART[T.LAVA] = { k:'lava', c:'#e0561c', fr:3, fps:2.5 }`(느리게).
- [ ] `TileArt.V` 를 4 → **6 이상**으로 올린다. 아틀라스 가로가 `V * TS` 이므로 메모리 영향은 미미하다. 애니메이션 타일은 **변형 대신 프레임**으로 그 칸들을 쓴다.
- [ ] `TileArt` 에 `ANIM = {}` 맵을 만들어 `build()` 에서 `ART[id].fr` 이 있는 타일을 등록하고, 프레임을 `v = 0..fr-1` 슬롯에 그린다.
- [ ] 렌더러(`game.js:2300`) 변형 선택을 이렇게 바꾼다:
  ```js
  const an = TileArt.ANIM[id];
  const v = an ? (((this.time * an.fps) | 0) % an.fr)
              : (tileHash(tx, ty) * VA) | 0;
  ```
  **주의**: 전 화면이 동시에 같은 프레임이 되면 부자연스럽다. 물결이 흐르는 느낌을 주려면 위치를 위상으로 섞을 것 — `(((this.time * an.fps) + tx * 0.5) | 0) % an.fr`.
- [ ] 손그림으로 갈 경우 `applySprite` 를 **가로 프레임 시트**를 받도록 확장한다(현재는 `TS×TS` 한 장 가정). `assets/manifest.json` 에 프레임 수를 함께 적을 것.
- [ ] **마그마 분포 교체**: 현재 용암은 `world.js:402` 의 `--- 6. 지옥 용암 ---` 블록이다. `HELL_Y+6` 부터 `WH-6` 까지 2D 노이즈(`n2(x+5000, y, 0.05, 2) > 0.66`)로 **낱개 타일을 흩뿌리고**, 아래 3칸 안에 바닥이 있을 때만 놓는다. 그래서 지금은 '용암 웅덩이'가 아니라 '용암 점박이'다. `HELL_Y`(390) 아래 최하단에 **호수 형태로 넓게 깔리도록** 바꾼다. 물 호수 생성(`fillPools` / `world.js:2145` 부근의 `T.WATER` 채우기)이 이미 침수 알고리즘을 갖고 있으니 **그 코드를 재사용**해 액체만 `T.LAVA` 로 바꾸는 방식을 권장한다. 중복 구현하지 말 것.
- [ ] 마그마 접촉 피해 판정이 이미 있는지 확인하고(`liq` 관련), 분포를 넓힌 뒤 **최하단 통행이 불가능해지지 않는지** 반드시 플레이로 확인할 것.

### D. 분수 rework · 전신주 기둥 · 풍차 확대

- [ ] 달성 시 `UI.chapterCard` 또는 `toast(..., 'good')` 연출 재사용.

## 3. 코드 규약 — 이 저장소의 스타일

- **주석은 한국어**로, "무엇을 하는가"가 아니라 **"왜 이렇게 했는가"** 를 쓴다. 기존 주석들이 과거의 버그와 그 원인을 기록하고 있다(예: `world.js:293-300` 성문 파묻힘 사고). 이 문화를 따를 것.
- 들여쓰기 2칸, 세미콜론 있음, `const`/`let`, 클래스는 `class`.
- 전역 싱글턴 `G`(게임), `UI`, `Sprites`, `Music`, `Sfx`, `Factory`, `TileArt`.
- 새 파일을 만들지 말고 **기존 파일의 해당 섹션에 넣을 것.** `game/index.html` 의 `<script>` 목록에 추가하면 캐시 무효화 값도 함께 손대야 한다.
- 타일 변경은 **반드시 `world.set(x, y, t)`** 를 통해서.

## 4. 웹사이트에 반영할 때 유의사항 ★★★

**게임만 고치고 끝내면 사이트가 거짓말을 하게 된다.** 릴리스 전에 이 절을 전부 훑을 것.

### 4-1. 빌드·배포 구조
- `site/play/` 는 `tools/build-site.sh` 가 `game/` 을 복사해 만든다. **`.gitignore` 되어 있으니 커밋하지 말 것.**
- 배포는 **Vercel** (`vercel.json` 의 `buildCommand: bash tools/build-site.sh`). GitHub Pages(`pages.yml`)는 수동 실행 예비 경로.
- 사이트 주소: 홈 `/home`, 다운로드 `/download`, 루트 `/` 는 `/home` 으로 리다이렉트. **실제 파일은 `site/home/index.html`, `site/download/index.html`.**
- 사이트 페이지가 한 단계 아래에 있으므로 **애셋 경로가 전부 `../` 로 시작한다**(`../style.css`, `../play/assets/...`). 이래야 끝 슬래시가 붙는 곳(GitHub Pages)과 안 붙는 곳(Vercel) 양쪽에서 같은 자리로 풀린다. **새 경로를 추가할 때 이 규칙을 지킬 것.**

### 4-2. 캐시 무효화 — 놓치기 쉬운 함정
- `game/index.html` 안에 `?v=183` 이 **12곳**(css 1 + js 11) 있다.
- **`game/` 의 css 나 js 를 고쳤으면 이 값을 반드시 올릴 것.** 안 올리면 재방문자가 옛 파일을 캐시에서 받아 새 코드와 섞인다.
- `vercel.json` 이 `/play/(.*).js` 를 1시간 캐시, `/play/assets/(.*)` 를 1년 immutable 로 걸어 두었다. **애셋 파일 내용을 바꾸면서 파일명을 그대로 두면 1년간 갱신되지 않는다** — 그림을 교체할 때는 파일명을 바꾸거나 매니페스트 경로에 버전을 붙일 것.

### 4-3. 사이트에 하드코딩된 수치 — v1.1에서 전부 바뀐다
`site/home/index.html:56-61` 의 통계 여섯 개:

| 표시 | 현재 값 | v1.1에서 확인 필요 |
|---|---|---|
| 종의 아이템 | 319 | 산소통·폭탄·화약·캔디 등 추가 → **재집계** |
| 종의 몬스터 | 79 | 세션 3 몹 추가 → **재집계** |
| 종의 기계 | 22 | 공장 레벨 4 → 변동 있으면 갱신 |
| 개 지역 | 11 | 바다·산맥·글리치 섬 → **14로** |
| 개의 장 | 15 | 세션 3 3장 → **18로** |
| 번의 결착 | 12 | 세션 3 보스 수만큼 증가 |

**`ITEMS`/`ENEMIES` 개수를 눈으로 세지 말 것.** 게임을 띄운 브라우저 콘솔에서 이렇게 확인한다.

```js
Object.keys(ITEMS).length        // 아이템
Object.keys(ENEMIES).length      // 몬스터
Object.keys(PETS).length         // 펫
CHAPTERS.length                  // 장
```

**주의**: 지금 사이트에 적힌 값이 이미 실제와 어긋나 있을 가능성이 있다(특히 몬스터 79). **기존 값에 더하지 말고, 위 명령으로 v1.1 최종 수치를 새로 뽑아 통째로 갈아 끼울 것.**

### 4-4. 사이트의 게임 데이터 복제본 — 게임과 따로 논다
- `site/content.js` 에 **`CHAPTERS` 와 `BOSSES` 배열이 통째로 복제되어 있다**(파일 머리 주석: *"게임 데이터가 바뀌면 여기도 같이 고쳐야 한다"*).
  - 세션 3 3장을 추가하면 여기에도 추가해야 한다.
  - 새 보스도 `BOSSES` 에 `[파일, 이름, 등장하는 장, 체력, 프레임폭, 프레임높이]` 형식으로.
- `site/showcase.js` 의 `REGIONS` 배열에 새 지역 3개를 추가해야 한다. 형식:
  `['이름', 'parallax_파일명', 지형시작y, '하늘색위', '하늘색아래', 밝기배수]`
  - **`지형시작y` 는 눈대중이 아니라 실측값이다.** 새 배경 PNG 의 첫 불투명 행을 다음으로 재라:
    ```python
    from PIL import Image
    im = Image.open('parallax_새지역.png').convert('RGBA'); px = im.load()
    for y in range(im.height):
        if any(px[x, y][3] > 8 for x in range(0, im.width, 5)):
            print('지형 시작 y =', y); break
    ```
  - **밝기 배수도 지역마다 따로 잡아야 한다.** 원경 그림들이 아주 어두워서(숲은 rgb(18,20,25)) 사이트 배경 위에 그냥 얹으면 안 보인다. 뒤에 하늘색을 깔고 밝기를 올려 다른 띠와 비슷하게 읽히도록 맞출 것.
- `site/showcase.js` 의 `BEASTS` 배열에 세션 3 몹을 넣을지 결정. 형식 `[파일명, 프레임폭, 프레임높이]` — 값은 `assets/manifest.json` 의 `characters.sheets` 에서 가져온다.

### 4-5. 스포일러 방지 규칙 — 이 사이트의 기존 방침
- `site/content.js` 상단:
  - `REVEAL_CHAPTERS = 5` — 5장 이후는 제목이 `???`, 그림은 CSS 로 흐림.
  - `REVEAL_BOSSES = 4` — 나머지 8마리는 실루엣만, 체력도 숨김.
- **세션 3 을 추가해도 이 값을 올리지 말 것.** 새 장·새 보스는 자동으로 가려진다.
- 홈의 기능 소개(`#loop` 섹션)는 v1.1 직전에 **의도적으로 9칸 → 6칸으로 줄이고** 던전 이름·방 수·펫 목록·보스 페이즈 같은 구체 정보를 뺐다. **세션 3 기능(수영·산소·폭탄·업적)을 소개할 때 이 기조를 유지할 것** — 지역 이름과 스토리는 밝히지 말고, 무엇을 하는 게임인지만.
