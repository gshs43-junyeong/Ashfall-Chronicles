## A. 시작 캐릭터 · 난이도 · 비석 · 설정

### A-1. 새로 생긴 데이터 (`js/data.js`)

| 이름 | 내용 |
|---|---|
| `CHARACTERS` | 시작 캐릭터 5종 — `id n tint story d base weapon bag (gold)` |
| `CHAR_OF(id)` | 못 찾으면 첫 번째를 돌려준다 (저장이 깨져도 안전) |
| `MODES` | `normal`(x1) · `hard`(x2 + 인벤토리 절반 떨굼) · `impossible`(x5 + 슬롯 삭제) |
| `MODE_OF(id)` | 위와 같음 |

| `SET_DEFAULT` | `view keys notice` 세 항목이 늘었다 |

### A-2. 게임 쪽 (`js/game.js`)

- `newGame(seedStr, slot, name, charId, mode)` / `_newGame(seed, name, charId, mode)`
  — **인자가 늘었습니다.** v1.1이 `newGame` 을 부르는 곳이 있으면 인자 수를 맞추세요.
- `modeMul()` → 난이도 배수. `Enemy` 생성자에서 `maxHp` · `dmg` 에만 곱합니다
  (경험치·금화는 안 건드립니다 — `scale()` 에 넣으면 보상까지 곱해집니다).
- `onDeath()` 가 난이도별로 갈립니다. `deathMark` 는
  `{ x, y, gold, xp, items, at }` 이고 `at = dayCount*1440 + dayT`,
  게임 내 12시간(720분)이 지나면 사라집니다. 거리 70 안에서 절반을 돌려받습니다.
- `resize()` — `this.W` / `this.H` 가 **화면 픽셀이 아니라 월드 좌표 크기**가 됐습니다
  (`innerWidth / z`). 배율은 `setTransform(dpr*z, …)` 에 들어갑니다.
  미니맵은 제 `MW/MH` 를 쓰므로 영향이 없습니다.
  **v1.1이 `this.W`/`this.H` 를 화면 픽셀로 쓰고 있으면 그쪽을 고쳐야 합니다.**
- `readInput()` — `I.wx = I.mx / z + this.cam.x` (배율 반영)
- `keysFor(id)` · `held(id)` · `isKey(id, code)` — 조작키 재설정용. 키 입력을
  `e.code === 'KeyX'` 로 직접 비교하던 곳은 `isKey('...', e.code)` 로 바꿔야 합니다.
- `toast(m, k)` 가 `settings.notice` 로 걸러집니다 (`'bad'` 는 항상 통과).
- `showNewGameForm(slot)` — 캐릭터·난이도 선택 UI가 들어갔습니다.

## C. 타이틀 재구성과 활 겨눔

### C-1. 타이틀에는 버튼 넷만

`싱글플레이 · 설정 · 크레딧 · 나가기`. 저장 슬롯과 캐릭터 선택은 팝업으로 뺐고,
`조작법`(옛 `#help-box`)은 설정 안 `조작키` 아래로 합쳤습니다.

| 없어진 것 | 대신 |
|---|---|
| `#help-box` · `#btn-help` · `#btn-help-close` | 설정 안 `조작법` 절 (`.set-help`) |
| 타이틀 안의 `#slot-list` | `#slots-screen` 팝업 안으로 이동 |
| 빈 슬롯 카드를 폼으로 바꾸던 방식 | `#newgame-screen` 팝업 (`#newgame-box`) |
| `.nf-*` css · `.slot-form*` css · `.ts-menu2` | `.ng-*` css · `.modal` / `.modal-box` |

새로 생긴 것: `#slots-screen` `#newgame-screen` `#credits-screen` `#bye-screen`,
`G.openModal/closeModal/closeTopModal/closeAllModals/quit`, `G.MODAL_STACK`.
타이틀에서 **Esc** 는 열려 있는 팝업을 한 겹씩 닫습니다.
`나가기` 는 `window.close()` 를 시도하고, 브라우저가 막으면 작별 화면을 띄웁니다.

`SET_DEFAULT`(game.js)에 `view` · `keys` · `notice` 가 빠져 있어 설정의 시야 범위가
`undefined%` 로 뜨던 것을 고쳤고, 조작키 이름표의 화살표 표기(`←↑→↓ Left`)를 바로잡았습니다.

### C-2. 활은 겨눈 쪽을 향한다

`wc === 'ranged'` 무기(활·쇠뇌·총)는 `drawHeldWeapon` 에서 자루 무기용 90° 보정을 쓰지 않고,
겨눔 각도(`G.aimAngle(p)` — `doAttack` 이 쓰는 각도와 같다)만큼 돌려 그립니다.
아이콘이 이미 오른쪽(+x)을 쏘는 그림이라 각도만 맞추면 됩니다.

`BOW_HAND`(18) · `BOW_TIP`(= BOW_HAND + 11.4) 은 `js/data.js` 에 있습니다.
그리는 쪽(game.js)과 쏘는 쪽(entity.js `fireProj(..., BOW_TIP)`)이 같은 값을 봐야
화살이 활 끝에서 나가는 것처럼 보입니다 — **한쪽만 고치지 마세요.**
`fireProj` 는 몸에서 활 끝까지를 반 칸 간격으로 훑어, 막힌 데가 있으면 거기서 화살을 냅니다
(벽에 붙어 쏠 때 화살이 벽을 건너뛰지 않게).

| 변형 | 하는 일 |

## E. 농사가 화면에 보입니다 (낚시는 뺐습니다)

### E-1. 낚시 — 만들었다가 **되돌렸습니다**

줄·찌·물결·입질 표시를 넣었다가 전부 뺐습니다. v1.1 로컬 작업에 이미 낚시 수정이
들어가 있어서, 같은 함수를 양쪽에서 고치면 병합이 지저분해지기 때문입니다.
**낚시 코드는 이 커밋 전과 한 글자도 다르지 않습니다.**

무엇이 문제였고 어떻게 고치면 되는지는 **`docs/v1.1-fishing-plan.md`** 에 코드까지
그대로 남겼습니다. v1.1 쪽 낚시 코드에 맞춰 골라 쓰시면 됩니다.
요약: 낚시는 지금 토스트로만 돌아가고 화면에 그려지는 것은 입질 순간 파티클 열 개뿐입니다.

### E-2. 농사 — 넣었습니다

**무엇을 고쳤나**

1. `World.growCrops(rng, dayF)` 가 **`{ grew: [키…], ripe: [키…] }` 를 돌려줍니다.**
   (예전에는 아무것도 안 돌려줬습니다.) `ripe` 는 이번 판에 다 여문 칸입니다.
   자란 칸을 알아야 게임 쪽에서 티를 낼 수 있어서입니다.
2. `G.update()` 의 작물 갱신 자리에서, 돌려받은 칸이 **화면 안이면** 파티클을 냅니다 —
   자란 칸은 잎(초록) 2개, 다 여문 칸은 금빛 5개. 화면 밖은 건너뜁니다(밭 하나가
   수백 칸일 수 있습니다).
3. `G.drawRipeCrops(c, camX, camY)` 를 새로 만들어 `drawPlayer` 앞에서 부릅니다.
   **다 여문 작물만** 천천히 반짝입니다. 칸마다 위상을 어긋나게 줘서 밭 전체가
   한꺼번에 깜빡이지 않습니다(그러면 경고등처럼 보입니다).
   `world.crops` 는 심은 칸만 들고 있어서 도는 양이 밭 크기만큼입니다.

**왜 고쳤나**

밭은 4초마다 타일만 조용히 바뀌었습니다. 보고 서 있어도 뭐가 자라는지 알 수 없었고,
한참 키워 놓고도 **어느 줄이 거둘 때가 됐는지** 알려면 타일 그림을 하나하나 들여다봐야
했습니다. 자라는 게 보이고, 거둘 것이 눈에 띄게 만드는 게 목적입니다.
밸런스·수확량·성장 속도는 **하나도 안 건드렸습니다** — 순전히 눈에 보이게 하는 것뿐입니다.

**병합 시** — `growCrops` 의 반환값이 바뀐 것이 유일한 시그니처 변경입니다.
v1.1에서 이 함수를 부르는 곳이 있으면 반환값을 무시해도 동작에는 지장이 없습니다.
농사 쪽도 겹칠 것 같으면 위 셋(반환값 · 파티클 · `drawRipeCrops`)만 빼면 되돌아갑니다.

## F. 유적마다 제 것이 하나씩 있습니다

유적 여덟 곳(바이옴 5 + 석판 3)에 **그 유적에서만 나오는 유물**을 하나씩 뒀습니다.
`RUIN_RELIC`(data.js) → 입구에서 **가장 먼 보물방 상자**에 확정으로 들어갑니다.
확률로 굴리지 않습니다 — 끝까지 들어간 값이어야 하기 때문입니다.

| 유적 | 유물 | 유적 | 유물 |
|---|---|---|---|
| 얼음 던전 | 서리 낀 창 | 부패한 둥지 | 썩지 않은 심 |
| 피라미드 | 멈춘 해시계 | 포자 굴 | 홀씨 방울 |
| 버려진 광산 | 마지막 안전등 | 석판 1·2·3 | 언 손자국 · 길 잃지 않는 눈 · 빈 씨앗 |

유적에 **처음 발을 들이면** 그 유적만의 카드가 한 번 뜹니다(`RUIN_CARD`,
`G.checkRuinEntry()`). 스포일러가 되지 않게 "무엇이 있다"가 아니라 "여기가 어떤
자리였나"를 말합니다. 본 유적은 `G.seenRuins` 에 남고 세이브에 실립니다.

곁들여 `World.ruinAt(tx,ty)` 가 생겼습니다(`inRuin` 은 이제 이걸 씁니다) — 유적
객체를 돌려주므로 어느 유적인지 알 수 있습니다. `world.ruins` 항목에 `id` 가 붙었고,
**옛 세이브의 유적에는 id 가 없어서** 카드가 조용히 안 뜹니다(오류는 아닙니다).

**아이템이 319 → 327 종이 됐습니다.** 사이트에 박힌 숫자를 v1.1 합칠 때 같이 고치세요
(§4-3 참고).

## G. 유적을 통째로 갈아엎었습니다 ★★

**v1.1 로컬 작업의 유적 입구 수정과 겹칩니다 — 이쪽으로 갈아 끼우세요.**
겹치는 것을 알고도 손댄 유일한 곳입니다(요청).

### H-1. 겉모양이 방 배치를 따라간다 (직사각형 탈출)

예전에는 `carveDungeon` 이 **직사각형을 통째로 벽으로 채우고** BSP로 잘랐습니다.
그래서 유적 여덟 곳의 겉모양이 전부 같은 상자였습니다.

이제 순서를 뒤집었습니다.
1. 먼저 BSP로 방을 뽑고
2. **도면(`plan`)** 의 `#` 칸에 든 방만 남기고
3. **남긴 방들의 자리만** 벽으로 채웁니다.

그래서 겉모양이 방 배치를 그대로 따라갑니다. `.` 칸은 손대지 않은 땅이라,
고리 도면이면 가운데가 통짜 암반으로 남아 O 자가 됩니다.

| 유적 | 도면 | 모양 |
|---|---|---|
| 얼음 던전 | `ring` | O — 가운데가 암반 |
| 피라미드 | `steps` | 계단식 (왼쪽 위 → 오른쪽 아래) |
| 버려진 광산 | `spine` | 두 덩이를 좁은 목이 잇는다 |
| 부패한 둥지 | `cross` | 十 |
| 포자 굴 | `horseshoe` | C — 한쪽이 트인 고리 |
| 석판 1·2·3 | `hook` · `tee` · `hall` | ㄴ · T · H |

도면은 `RUIN_PLANS`(data.js)에 글자 그림으로 있습니다. 새 도면을 넣으려면 거기
줄 세 개를 적으면 됩니다. 도면이 너무 빡빡해 방이 셋도 안 남으면 생성기가 도면을
버리고 통짜로 팝니다(막힌 유적을 만들지 않는 안전장치).
**도면을 안 주면 결과가 예전과 완전히 같습니다** — 마을 던전·공창 등 다른 곳은 그대로입니다.

**★ 반드시 지킬 것 — 연결 보장.**
`buildRuinSite` 끝과 석판 유적 반복문 끝에서 `_ensureConnected` 를 **한 번 더** 부릅니다.
`carveDungeon` 안에서도 하지만, 그 뒤에 바닥을 통째로 갈아 까는 방(얼어붙은 회랑의
얼음 바닥, 포자 정원의 이끼 바닥)이 그리로 지나가던 굴을 도로 메웠습니다 —
실측으로 포자 굴이 10칸 중 4칸만 닿았습니다. 마지막 한 번을 넣으니 여섯 씨앗 전부
**못 닿는 방 0개**가 됐습니다. 유적 생성에 무엇을 더 얹든 이 호출은 맨 끝에 두세요.

**★ 장식 규칙 — 걷는 줄을 막지 않는다.**
바닥 타일은 `fy+1`, 플레이어 키가 두 칸이라 `fy` 와 `fy-1` 이 통로입니다.
처음에 얼음 기둥과 석상을 바닥까지 세웠더니 방문을 그대로 봉했습니다.
- 막는 타일(`solid: 1`)은 **천장 쪽에만**, 또는 **이미 벽인 자리를 갈아끼울 때만**
- 걷는 줄에는 통과되는 타일(`solid: 0` — 횃불·가시·이끼갓·부패잎)만

### H-2. 지상 입구를 줄이고, 지도로 찾게 했다

여덟 곳 중 여섯이 지상에서 걸어 들어갈 수 있었습니다. 이제:

| 입구 | 유적 | 어떻게 |
|---|---|---|
| `gated` | 버려진 광산 | 문틀까지 세운 뚜렷한 입구 (첫 유적이라 하나는 남긴다) |
| `surface` | 피라미드 | 윗부분이 지상으로 솟아 있다 (그게 피라미드다) |
| `sunken` **(새로 만듦)** | 석판 1·2·3 | 통로가 지표 아래 4~7칸에 묻혀 있다. 지상에는 **부러진 기둥 하나**와 흩어진 벽돌뿐 — 눈에는 띄지만 파 내려가야 열린다 |
| `buried` | 얼음 · 부패한 둥지 · 포자 굴 | 입구가 아예 없다. **위치 지도**를 구해야 찾는다 |

**위치 지도**(`type: 'map'` 아이템 3종)는 그 유적이 아니라 **다른 유적의 보물방 상자**에
들어갑니다 — 한 곳을 털면 다음 곳이 열리는 사슬입니다(`RUIN_MAP_IN`).

```
광산(입구 있음)  → 얼어붙은 골짜기 지도 → 얼음 던전
피라미드(솟아 있음) → 포자 굴 지도      → 포자 굴 → 둥지 지도 → 부패한 둥지
```

지도를 우클릭으로 펴면 그 유적 자리가 **나침반에 잡히고**(`questTargets` 의 `k: 'ruin'`,
황금색 화살표) 지도는 사라집니다. 그 유적에 한 번 들어가 보면 표시를 거둡니다.
표시는 `G.ruinMarks` 로 세이브에 남습니다.

### H-3. 유적마다 제 것 — 방 · 장식 · 이벤트 · 전리품

| 유적 | 고유 방 | 고유 이벤트 | 장식 | 상자 덤 |
|---|---|---|---|---|
| 얼음 던전 | 얼어붙은 회랑 (바닥이 통째로 얼음, 천장 고드름) | **blackout** — 불이 한꺼번에 꺼지고 서리 것들이 몰려온다 | 천장에서 내려오는 얼음 기둥 | 얼음 조각 |
| 피라미드 | 빛우물 (천장에 뚫린 구멍 + 제단) | **password** — 숫자 세 자리를 맞춰야 열리는 골방 | 벽에 새긴 좌상 | 금광석 |
| 버려진 광산 | 무너진 갱도 (바닥 절반이 부서지는 바닥) | **collapse** — 발밑이 내려앉는다 | 천장을 받치는 갱목 | 석탄 |
| 부패한 둥지 | 둥지의 심장 (천장에 매달린 살덩이) | **swarm** — 둥지가 깨어난다 (8마리) | 벽에서 자라나온 부패잎 | 부패의 정수 |
| 포자 굴 | 발광 버섯 정원 | **bloom** — 홀씨가 터져 한동안 독에 잠긴다 | 무리 지어 자란 갓 | 버섯 |

석판 유적 셋도 같은 규격을 씁니다(`STORY_RUIN`) — 예전에는 이 셋만 별도 코드라
바이옴 유적을 고쳐도 여기엔 안 미쳤습니다.

**암호문(`codedoor`)** — 세 자리 숫자는 **세계 씨앗에서 뽑으므로 세계마다 다릅니다**
(`G.ruinCode(id)`). 그 유적 안 **비문 흔적 세 개에 한 자리씩** 흩어져 있어서,
돌아다니며 셋을 다 읽어야 열립니다(`readLorestone` 이 흔적 아래에 한 줄 덧붙입니다).
문 너머에는 그 유적에서 가장 좋은 상자가 있습니다.

**이벤트는 고유 방을 밟는 순간 한 번만** 터집니다. 구역은 `world.ruinEvents`(세이브에
실림)에 있고, `world.objects` 가 **아닙니다** — objects 는 우클릭 대상 목록이라
방 하나만 한 상자를 끼워 넣으면 그 방 안의 진짜 상자·비문을 가려 버립니다.
겪은 이벤트는 `G.ruinEvDone` 에 남습니다.
`blackout` 은 타일을 지우지 않고 **화면만 덮습니다** — 장식을 부수면 되돌릴 수가 없습니다.

### H-5. 몹 · 방 모양 · 테마 장식 · 불규칙한 입구 · 새 함정

- **유적마다 몹이 다릅니다.** `RUIN_SPEC[].mobs` 를 `zoneTable('ruin', …)` 이

- **방이 위아래로 길쭉하지 않습니다.** `bspSplit` 의 자르는 방향 규칙을 고쳤습니다

  31% → 3~4%, 가로/세로 평균 2.0 이 됐습니다.
- **방이 스무 개 넘는 유적이 둘.** `RUIN_SPEC` 의 크기와 `bsp` 를 올려

- **테마 장식.** `putRuinDecor` 가 `[종류, 타일, 밀도]` 목록을 받습니다.

  ★ 규칙: **장식은 걷는 줄(fy · fy-1)을 절대 막지 않습니다.** 처음에 얼음 기둥을
  바닥까지 세웠더니 방문을 봉해서 유적 절반이 못 들어가는 곳이 됐습니다.

  막다른 곁방(상자 아니면 함정)이 붙기도 하고, 방마다 그 유적의 함정이 최소 하나

  **세션 2 권역(부패한 둥지 · 포자 정원)에 전기 함정을 더 세웠습니다.**

### H-6. ★ "걸어서 보스까지 갔다가 나올 수 있는가"를 실제로 검사합니다

지금까지의 연결 검사(`_ensureConnected`)는 **빈 칸이 이어져 있는가**만 봤습니다.
사람은 빈 칸을 헤엄쳐 다니지 않습니다 — 발 디딜 곳이 있어야 하고 한 번에 세 칸까지만
오릅니다. 새로 만든 진단 도구로 재 보니 굴은 다 뚫려 있는데도 이랬습니다.

| 유적 | 걸어 닿는 방 | 보스에서 밖으로 |
|---|---|---|
| 갱도 | 3 / 10 | 못 나감 |
| 부패한 둥지 | 7 / 33 | 못 나감 |
| 얼어붙은 회랑 | 7 / 8 | 못 나감 |
| 모래 피라미드 | 10 / 19 | 나감 |
| 포자 정원 | 7 / 9 | 나감 |
| 심층 봉인실 | — | 못 나감 |

그래서 **생성기가 스스로 걸어 보고 고치게** 했습니다(`world.js`).

- `_standSet(box, x, y)` — 플레이어와 같은 이동 규칙으로 "설 수 있는 칸"을 모읍니다.
  규칙은 `entity.js` 의 실제 물리에서 뽑았습니다(점프 620 · 중력 2000 → 최고 96px ≈
  4.4칸이라 보수적으로 3칸). 발판은 밟고 서거나 아래 키로 뚫고 내려가고, 물에서는 뜹니다.
- `_digStair(a, b)` — 두 자리를 잇습니다. 가로 굴은 발밑을 채워 허공에 안 뜨게 하고,
  세로 굴은 두 칸 폭에 세 칸마다 발판을 놓습니다. **이미 있는 발판은 절대 지우지
  않습니다** — 지웠더니 앞서 세운 사다리 중간이 여섯 칸으로 벌어져 "팠다 막았다"를
  무한히 되풀이했습니다.
- `_ensureWalkable(…)` — 기준점을 바꿔 가며 **가는 길과 오는 길을 번갈아** 손봅니다.
  오르내림은 대칭이 아니어서(떨어지는 건 공짜, 올라오는 덴 발판이 필요) 한쪽만 보면
  "들어는 갔는데 못 나오는" 유적이 남습니다. 실측에서 석판 유적 2가 들어가기는
  28/28인데 나오기는 8/28이었습니다.
- 검사 자리에는 방마다 두 곳(왼쪽 끝·한가운데)과 **입구 통로의 작은 방들, 입구 목**이
  모두 들어갑니다. 그래서 "지상 → 보스 → 지상"이 통째로 검사됩니다.
- 이 손질은 **세계를 다 만든 뒤**에 돕니다(`generate()` 끝). 유적을 지은 다음에도 큰
  동굴·물웅덩이·심층 갱도가 유적을 가로질러 바닥을 헐고 지나가기 때문입니다.

곁들여 고친 것:
- 입구 통로의 **발판을 어느 성격(entryKind)이든 세 칸마다** 남깁니다. 예전에는
  `foothold` 만 발판이 있어서 나머지는 한 번 떨어지면 못 올라왔습니다. 내려가는 길의
  사나움은 발판이 아니라 함정과 가시로 냅니다.
- 통로의 작은 방마다 **바닥에서 천장 구멍까지 되짚어 올라가는 디딤판**을 놓습니다.
- **심층 봉인실**: 문턱(ky+4)과 복도 바닥 높이를 맞추고, 안쪽에 바닥에서 문턱까지
  세 칸씩 끊어 오르는 발판 두 줄을 세웠습니다. 방·문·복도를 다시 세우는
  `restoreSealRoom()` 을 세계 생성 맨 뒤에서 한 번 더 부릅니다 — 동굴이 봉인실 바닥을
  스물일곱 칸이나 헐고 지나가고 있었습니다. **봉인문 두 줄은 어떤 경우에도 안 건드립니다.**

새 도구 **`tools/ruindiag.py`** — 브라우저에서 실제로 세계를 만들고, 보스 자리에서
플레이어와 같은 이동 규칙으로 걸어 보고, 방·상자에 얼마나 닿는지와 이벤트·암호문·
신비한 방·유물·지도가 제대로 도는지 셉니다.

```
python3 -m http.server 8777    # game/ 에서
python3 tools/ruindiag.py d1 d2 d3 d4 d5 d6
```

씨앗 여섯 개 실측 결과: **문제 0건.** 방 도달률은 한 곳(포자 정원 d4 7/8)만 빼고
전부 100%, 입구가 있는 유적은 전부 "보스에서 밖으로" 통과입니다. 입구 없는 유적
(`arch: 'buried'`)은 애초에 파고 드나드는 곳이라 "걸어서 나가기"를 묻지 않습니다.

세계 생성 시간은 0.47초 → 1.05초입니다(검사·손질에 약 0.5초).

### H-7. 유적 지도를 얻는 길이 셋

입구 없는 유적마다 위치 지도를 **세 곳**에서 얻을 수 있습니다(`buildRuinCaches`).

1. **유적 바로 위 지표 아래 은닉처** — 지상에 돌무지 표식이 서 있고, 그 밑을 파면
   작은 방에 상자가 있습니다. "여기 아래에 뭔가 있다"를 지상에서 알 수 있는 길.
2. **세계 어딘가의 동굴 상자** — 유적과 아무 상관 없는 자리라, 굴을 파다 우연히
   만나는 길. 지도가 유적 안에만 있으면 첫 유적을 못 연 사람은 영영 못 엽니다.
3. **다른 유적의 보물방** (`RUIN_MAP_IN`) — 한 곳을 털면 다음 곳이 열리는 사슬.

어느 길로 얻어도 같은 지도이고, 이미 자리를 알면 "이미 자리를 안다"가 뜹니다.
실측으로 씨앗마다 지도 상자 9개(지도 3종 × 길 3개)가 놓입니다.

## I. 화면과 시작 장비 (짧은 손질 넷)

### I-1. 플레이어 그림이 잘려 보이던 것

`char/player*.png` 는 20x40 프레임에 그림을 **가장자리까지 꽉 채워** 구워져 있었습니다.
실측하면 열세 프레임 전부 이렇습니다.

- 정수리(y=0)에 **윤곽선이 없습니다.** 좌우에는 있는데 위만 없어서 머리가 칼로 자른 듯
  납작합니다. "짤려 보인다"의 대부분이 이것입니다.
- 공격 자세 몇 장은 팔이 x=0 · x=79 를 넘어가 **채움색 그대로 끊깁니다.**

새 도구 **`tools/unclip.py`** 가 프레임을 사방 한 논리픽셀 넓히고 **잘린 자리에만**
윤곽선을 채웁니다. 이미 윤곽선이 있는 가장자리는 손대지 않습니다 — 덧대면 선만
두 겹으로 두꺼워집니다.

    20x40 (80x160)  ->  22x41 (88x164),  그림은 (4,4) 에 놓입니다

같이 바뀐 것:

| 파일 | 무엇 |
|---|---|
| `assets/manifest.json` | 플레이어 시트 6장의 `frameW` 22 · `frameH` 41 · `ox`/`oy` -1 |
| `assets/sprites.js` | `draw()` 가 `ox`/`oy` 를 반영. 그림 크기가 매니페스트와 다르면(캐시에 옛 그림이 남았을 때) **그림 쪽을 믿고** 프레임 크기를 다시 잽니다 |
| `css/style.css` | 캐릭터 선택 초상 `.ng-char .por` 44x82 · `.por-big` 88x164 |
| `tools/mkchars.py` | 여백이 붙은 시트를 읽으면 벗겨 내고 옛 규격으로 작업합니다 |

`ox`/`oy` 는 그린 자리를 그만큼 되밀어, 몸은 있던 자리(판정 박스 20x40)에 그대로 섭니다.

### I-2. 설정 창을 세 갈래로

한 줄로 이어 붙인 탓에 세로가 화면 높이의 두 배를 넘었고, 조작키를 보려면 한참
굴려 내려가야 했습니다. **화면·소리 / 알림 / 조작** 세 갈래로 나누고, 머리(탭)와
발(기본값·닫기)은 붙박이로, 가운데만 구르게 했습니다. 항목이 많은 알림·조작키는
두 칸으로 접었습니다.

가장 긴 갈래(조작)가 647px — 780px 창에서 스크롤 없이 다 들어옵니다.
열 때는 늘 첫 갈래로 돌아갑니다(`UI.setTab`).

### I-3. 시작 무기 넷의 초당 피해를 맞췄습니다

예전에는 곡괭이로 시작하는 굴 파는 이만 13.2 였습니다. 고른 캐릭터 하나 때문에
초반이 통째로 팍팍했습니다.

| 캐릭터 | 무기 | 예전 | 지금 |
|---|---|---|---|
| 떠돌이 | 금 간 목검 | 9 x 2.2 = 19.8 | 그대로 |
| 굴 파는 이 | **날카로운 곡괭이**(새것) | 구리 곡괭이 6 x 2.2 = 13.2 | 9 x 2.2 = **19.8** |
| 사냥꾼 | 사냥용 활 | 11 x 1.9 = 20.9 | 10 x 2.0 = **20.0** |
| 수련생 | 옹이진 나뭇가지 | 12 x 1.7 = 20.4 | 11 x 1.8 = **19.8** |

성격 차이(사거리 · 마나 · 탄속)는 그대로 두고 숫자만 맞췄습니다.

**곡괭이는 다섯 모두가 들고 시작합니다.** 없으면 첫 돌에서 막혀 시작이 안 됩니다.
곡괭이를 무기로 드는 굴 파는 이만 구리 곡괭이 대신 `pick_sharp`(날카로운 곡괭이)를
듭니다 — **채굴 등급(power 1)과 속도(2.2)는 구리 곡괭이와 같고 공격력만 6 -> 9** 입니다.
'빈손'도 이제 곡괭이 한 자루를 들고 시작합니다(무기는 여전히 없습니다).

아이템이 하나 늘었습니다(`pick_sharp`) — 홈페이지의 아이템 개수는 v1.1 합칠 때 같이.

  (개발 중에는 `?v=` 를 안 올리므로 흔합니다), 옛 `game.js` 에는 걷어 줄 코드가 없어
  **무한 로딩**이 됩니다 — 실제로 그렇게 갇혔습니다. 안전장치를 스크립트 파일에 두면
  그 파일이 같이 옛것일 때 소용이 없으므로 HTML 안에 둡니다.

  | `window.__acBooted` | `G.bootDone()` | 정상적으로 부팅이 끝났다 |

  `load` 뒤 0.2초에 `__acBooting` 이 없으면(= 옛 game.js) 곧바로 걷고,
  6초 뒤에도 `__acBooted` 가 없으면(= 애셋이 안 옴) 그때 걷습니다.

## J. 유적 함정 · 암호문 창 · 바이옴

### J-1. 사이트 히어로에서 사람이 잘려 보이던 것

`site/hero.js` 는 걷는 사람을 `GROUND + 12` 에 세우고, 아래쪽 페이드를 `GROUND - 90`
에서부터 덮었습니다. 그래서 다리와 신발이 통째로 먹혀 **잘린 것처럼** 보였습니다.
발끝을 지면 줄(`GROUND + 4`)에 맞추고, 페이드를 딛는 줄 아래(`GROUND - 16` ~ `+26`)로만
두고 그 아래는 통째로 바탕색으로 채웁니다. 게임 타이틀 배경도 같은 규칙입니다.

### J-2. 암호문은 이제 게임 안 창

`window.prompt()` 를 쓰고 있었습니다. 창 밖에 뜨는 데다 그동안 게임이 통째로 얼어붙어,
유적 한복판에서 브라우저 대화상자를 마주하는 꼴이었습니다.

새 창 `#code-screen` — 세 자리만 받는 큰 입력칸, 틀리면 자리에서 알려 주고 비웁니다.
세 자리를 채우면 바로 맞춰 보고, Enter · 확인 버튼 · 바깥 클릭 · Esc 를 다 받습니다.
`G.openCodeDoor` / `G.tryCodeDoor` / `G.closeCodeDoor` 셋으로 나뉘어 있어 진단에서도
같은 길을 그대로 밟습니다.

### J-3. 함정 없이 그냥 걸어 들어가는 문은 없습니다

들어가는 쪽인지 나오는 쪽인지 가리지 않습니다. 세 군데를 막았습니다.

1. **입구 통로의 작은 방** — 원래 방마다 하나씩 심었는데, 화살 구멍·톱니 같은 것은
   벽이 있어야 박히므로 갓 파낸 방에서는 **아무것도 안 놓고 조용히 지나갔습니다.**
   `putTileTrap` 이 이제 놓았는지를 돌려주고, 못 놓으면 다른 종류로 물러섭니다.
2. **통행 보수로 판 계단** — 그 길에는 유적 밖으로 빠지는 길도 있어, 그대로 두면
   함정 하나 없는 샛길이 생겼습니다. 새 `putPathTrap` 으로 하나씩 심습니다.
   ★ 방에 놓는 함정을 그대로 쓰면 안 됩니다 — 화살 구멍·방전 코일·톱니·가스는
   **전부 `solid: 1`** 이라 좁은 통로에 놓이면 길을 봉해 버립니다(실측에서 보수로 판
   계단이 그렇게 막혀 유적 하나가 통째로 끊겼습니다: 방 24곳 중 0곳 도달).
   그래서 길목에는 **가시(통과)와 부서지는 바닥(바닥)** 둘만 씁니다.
3. **마지막 훑기** — 통로를 판 뒤에도 다음 방의 벽 세우기·목 뚫기·통행 보수가 앞서
   놓은 함정을 지웁니다. 세계를 다 만든 뒤 `ensureEntranceTraps()` 가 한 번 훑어
   빠진 방만 채웁니다. 여기가 타일을 건드리는 마지막 자리입니다.

진단에 `입구함정` 칸이 생겼습니다(작은 방 중 몇 곳이 함정을 물고 있는가).
씨앗 여섯 개에서 **전부 8/8 · 3/3** 입니다.

### J-4. 사라지는 타일은 밑이 빈 자리에만

`putTileTrap` 의 부서지는 바닥은 방 바닥 줄에 그냥 얹혔습니다. 그 밑은 대개 단단한
암반이라 밟아서 무너져도 한 칸 내려서는 것으로 끝났습니다 — 사라져도 아무 일이 없었습니다.

이제 **밑이 빈 자리를 먼저 찾고**, 없으면 **두 칸짜리 구덩이를 같이 팝니다.**
깊이를 두 칸으로 묶은 것은 점프(세 칸)로 반드시 다시 올라올 수 있게 하려는 것입니다.
개수를 정하는 규칙(`rng.int(2,4)` 씩, 같은 횟수)은 그대로라 **밀도는 예전과 같습니다** —
실측으로 한 세계에 100~140칸이고, 그중 밑이 빈 것이 **100%** 입니다(예전에는 0에 가까웠습니다).

### J-5. 바이옴 이름표와 공기색

- **이름표** — 처음 발을 들일 때 유적과 같은 카드가 한 번 뜹니다(`G.checkBiomeEntry`).
  ★ 무엇이 사는가가 아니라 **그 땅이 어떤 곳인가**를 적습니다. 경계 띠(24칸) 안에서는
  알리지 않아, 경계를 오갈 때 카드가 번갈아 뜨지 않습니다. 세이브에 `seenBiomes` 로 남습니다.
- **공기색** — 땅마다 다른 색을 화면에 아주 옅게 덮습니다(`G.biomeAir`).

## K. 상자 · 암호 골방 · 이름표 · 공기색 (2차 손질)

### K-1. 유적 상자를 절반 아래로

방마다 상자가 있어 여는 맛이 없었습니다 — 유적 하나에 스물 가까이 놓이고 있었습니다.

| 어디 | 예전 | 지금 |
|---|---|---|
| `RUIN_SPEC[].chestRate` | 0.30~0.52 | 0.14~0.24 |
| 거리 보정 | `+ far * 0.35` (far 가 2를 넘기도 했다) | `+ min(1, far) * 0.14` |
| 입구 곁방 | 0.50 | 0.22 |
| 석판 유적 방 | `sp.chest` | `sp.chest * 0.45` |

보물방·보스방·암호 골방의 **확정 상자는 그대로** 두어 "털 만한 것"은 줄지 않습니다.
실측으로 유적 하나에 1~14개(대개 3~9개)입니다.

### K-2. 입구 방마다 서로 다른 함정이 여럿

한 갈래만 놓으면 첫 방을 보고 나머지를 다 아는 길이 됩니다. 방마다 **서로 다른 갈래를
둘 이상** 심고, 개수도 방마다 다르게(2~4) 굴립니다. 자리는 `putTileTrap` 이 방 안에서
무작위로 고릅니다.

★ 심는 자리를 **맨 마지막으로 옮겼습니다.** 통로를 팔 때 심어도, 그 뒤에 다음 방의
벽을 세우고 · 목을 뚫고 · 통행 보수로 굴을 파면서 지워집니다 — 실측하면 방 서른다섯
곳 중 열대여섯이 한 갈래만 남았습니다. 이제 `ensureEntranceTraps()` 가 세계를 다 만든
뒤 갈래 수를 세어 모자란 만큼 채웁니다. **방당 평균 2.3갈래**, 한 갈래뿐인 방 3~4곳.

### K-3. 암호 골방은 캘 수 없는 돌로 두른다

문만 봉인석이고 벽·천장·바닥은 평범한 유적 벽돌이라, **암호를 풀 것 없이 옆을 파고
들어가면 그만**이었습니다.

- 새 타일 `T.CIPHERSTONE`(암호석) — `hard: 99` 라 어떤 곡괭이로도 캘 수 없습니다.
  색은 유적 벽돌(`#6a6250`)에서 크게 벗어나지 않는 `#5f5947` 에 룬빛만 옅게 얹어,
  기존 유적 구조 안에서 겉돌지 않습니다.
- 골방 여섯 면을 통째로 암호석으로 두릅니다. 문(암호문)만이 입구입니다.
- **굴착·함정이 이 돌을 갈아엎지 못하게** 막았습니다 — `world.locked(x,y)` 를
  `_digStair` · `_ensureConnected` · `putPathTrap` · 부서지는 바닥이 모두 봅니다.
  (실측: 막기 전에는 골방 바닥이 부서지는 바닥으로 바뀌어 다섯 칸이 뚫려 있었습니다.)
- 그래도 한 칸이 새는 씨앗이 있어, 타일을 건드리는 **맨 마지막**에
  `sealCipherVaults()` 가 껍질을 한 번 더 세웁니다. 씨앗 넷에서 샌 곳 0.

### K-4. 이름표는 **원경이 바뀔 때** 뜬다

예전에는 "바이옴 경계에서 24칸 안쪽"이라는 자체 기준을 썼습니다. 이제 `G.bgId()` 가
`drawParallaxArt` 와 **같은 규칙**으로 지금 깔린 원경을 알아내고, 그 값이 바뀌는 순간에
띄웁니다 — 눈에 보이는 배경이 바뀌는 자리가 "다른 땅에 들어섰다"고 느끼는 자리입니다.

덕분에 **베이스캠프와 여명 마을**도 자연히 이름표를 갖습니다(제 배경 그림을 쓰므로).
`ZONE_CARD` 에 두 곳을 적었습니다. 유적·하늘 섬·지옥은 제 카드가 따로 있어 건너뜁니다.

### K-5. 공기색을 두 배 반 (세션 2 권역은 더)

0.05 안팎이라 눈에 거의 안 잡혔습니다.

### K-6. 홈페이지 사람이 잘려 보이던 진짜 이유

지난번에 아래쪽 페이드를 고쳤는데도 남아 있었습니다. 원인은 **최근접 확대·축소를 두 번
겹친 것**이었습니다 — 88x164 그림을 0.92배(81x151)로 한 번 깎고, 그 결과를 다시 캔버스
변환(예: 2.25배)으로 늘리면 픽셀 열이 들쭉날쭉 겹치거나 빠져서 팔과 발이 잘려 보입니다.
배경 능선처럼 **원본 크기 그대로** 그리게 했습니다. 게임 타이틀의 걷는 사람도 같은
이유로 원본의 **정수 배**로만 키웁니다.

### K-7. 타이틀 배경이 처음에 안 뜨던 것

`TitleBG.start()` 를 `bootDone()` 에서만 불렀습니다. 애셋이 늦게 오면 `index.html` 의
안전장치가 먼저 로딩을 걷어 버려, 타이틀은 떴는데 배경 캔버스는 빈 채로 남았습니다 —
설정이나 크레딧을 열었다 닫으면 그제서야 보였습니다(그 사이에 `bootDone` 이 끝났을
뿐입니다). 이제 `G.init()` 에서 **바로 켭니다.** 그림이 아직 없어도 하늘·잔광·재는
그릴 수 있고, 그림이 붙으면 `useSprites()` 가 능선과 사람을 얹습니다.

### K-8. 돌아오는 길 검사의 "빠른 길"을 걷어냈다

`_walkBack` 이 "돌아올 수 있는 자리에서 걸어 닿는 칸은 전부 돌아올 수 있다"고 보고
같은 구역을 건너뛰고 있었습니다. **오르내림은 대칭이 아닙니다** — p 에서 X 로 갈 수
있다고 X 에서 돌아올 수 있는 것은 아닙니다. 그래서 하필 **한 방향으로 떨어져 들어가는
자리를 그 방법으로 건너뛰고** 있었습니다(실측: 석판 유적 1이 들어가기는 22/22인데
나오기는 스물한 칸뿐이었습니다). 자리마다 정직하게 걸어 보되, 한 방에서는 가운데
한 자리만 봅니다(세 번째 값 0 이 "곁자리"를 뜻합니다). 세계 생성 1.0초 -> 1.6~2.0초.

## L. 특성이 트리가 되었습니다 · 생활 숙련 ★

### L-1. 표 나열 -> 트리

예전 특성 화면은 **목록**이었습니다. 분기마다 여섯 줄이 위아래로 놓여 있고,
티어 요구 포인트만 넘기면 어느 줄이든 마음대로 찍혔습니다. "무엇 다음에 무엇"이라는
관계가 코드에도, 화면에도 없었습니다.

이제 각 칸은 **자리와 이어진 윗칸**을 가집니다.

- `tier` 0~3 — 세로 단. `TIER_REQ` 만큼 그 분기에 포인트가 쌓여야 열립니다
- `col` 0~2 — 가로. `.5` 는 두 칸 사이라 트리 모양이 잡힙니다
- `req` — 이어진 윗칸들. **하나라도** 배웠으면 아래가 열립니다(전부가 아닙니다)

화면에서는 4단 × 3열의 판이 되고, 칸과 칸은 SVG `<line>` 한 겹으로 이어집니다.
선의 `x` 가 백분율이라 판 너비가 바뀌어도 따라옵니다. 칸에 마우스를 올리면
지금 랭크와 **다음 랭크의 수치**를 나란히 보여 주고, 잠겨 있으면 왜 잠겼는지를
문장으로 말합니다("이 분기에 5포인트 필요 (지금 3)", "윗단계 화염구 또는 심연의 지혜를 먼저").

### L-2. 칸이 열둘 늘었고, 요구 포인트는 줄었습니다

분기마다 여섯 칸이던 것이 **열 칸**이 되었습니다(2 / 3 / 3 / 2).

| 분기 | 새로 생긴 칸 |
|---|---|
| 검투사 | 철벽(액티브) · 대지 가르기(액티브) · 전투 함성(액티브) · 불굴(패시브) |
| 유격 | 꿰뚫는 화살(액티브) · 연막탄(액티브) · 사냥꾼의 표식(액티브) · 폭풍의 시위(패시브) |
| 비전 | 비전 방벽(액티브) · 사슬 번개(액티브) · 차원 도약(액티브) · 별의 낙하(액티브) |

칸이 늘어난 만큼 **드는 값은 내렸습니다**.

- `TIER_REQ` 3 / 7 / 12 -> **2 / 5 / 8**
- 오래 걸리던 몇 칸의 최대 랭크를 한 단계 낮췄습니다
  (단련된 몸·매의 눈·심연의 지혜 5->4, 피의 갈망·질풍 보행·치유의 빛 4->3)
- 특성 포인트가 **두 레벨에 하나 -> 레벨마다 하나** (`entity.js` `addXp`)

옛 기록을 불러올 때는 이미 쓴 랭크를 세어 "이 레벨이면 받았어야 할 만큼"까지
채워 줍니다(`_loadGame`). 안 그러면 옛 기록만 손해입니다.

### L-3. 새 칸이 실제로 하는 일

전부 그리기와 판정을 따로 붙였습니다. 그림 파일은 새로 만들지 않았고,
아이콘 열두 개는 `itemart.js` 에 **선으로 그렸습니다**(`bulwark`·`quake`·`shout`·
`lifebeat`·`pierce`·`smoke`·`mark`·`tempest`·`barrier`·`chain`·`blink`·`meteor`).

- **철벽** — `dr` 이라는 값이 새로 생겼습니다. 방어(`def`)와 달리 적 수치를 타지 않고
  **최종 피해를 그대로 깎습니다**(겹쳐도 80%가 한계). 방어를 아무리 쌓아도 못 버티는
  한 방을 한 번 넘기라고 만든 값이라, 짧은 버프에만 붙어 있습니다. 넉백도 무시합니다.
- **대지 가르기** — 발밑을 따라 좌우로 다섯 마디씩 충격파가 퍼집니다.
- **전투 함성** — 피해가 아니라 **떼어 내기**입니다. 붙어 있던 것들을 밀치고 둔화시킵니다.
- **불굴** — 죽는 그 한 번을 넘깁니다(체력 1 + 최대 체력 25% 회복, 120초에 한 번).
- **꿰뚫는 화살** — `pierce: 6` 짜리 빠른 한 발.
- **연막탄** — 잠깐 무적 + 이동 속도 + 주변 둔화.
- **사냥꾼의 표식** — 적에게 붙는 값입니다(`markT`/`markAmt`). 출처를 가리지 않아서,
  표식이 붙은 동안은 **무엇에 맞아도** 더 아픕니다.
- **폭풍의 시위** — 원거리 공격이 30% 확률로 한 발 더 나갑니다(`doAttack` 의 `ranged` 갈래).
- **비전 방벽** — `p.shield` 를 채웁니다. 맞으면 체력보다 **먼저** 깎이고,
  다 깎이면 그 자리에서 깨집니다. 남아 있는 동안 플레이어를 감싼 육각 결계가 그려집니다.
- **사슬 번개** — 가까운 적으로 옮겨 붙으며 한 번 튈 때마다 25%씩 옅어집니다.
- **차원 도약** — 겨눈 쪽으로 최대 190px. 반 칸씩 훑어 **뚫린 데까지만** 갑니다.
- **별의 낙하** — 떨어질 자리를 0.9초 동안 예고하고 나서 떨어집니다. 피할 시간을 줍니다.

연출을 셋 더 만들었습니다(`game.js`). 입자만으로는 무슨 일이 일어났는지 안 보이는
것들이 있어서입니다 — `ringFx`(퍼지는 고리) · `boltFx`(튀는 번개) · `warnFx`(떨어질 자리).
전부 그림 없이 선으로만 그립니다.

**트리 자체의 연출**도 넣었습니다. 찍은 칸이 한 번 부풀고 둘레로 불티가 튀며,
그 칸에 닿는 선으로 빛이 흐릅니다(CSS 애니메이션 `nodepop`·`nspark`·`blineflow`).
배운 칸은 분기 색으로 테두리가 살고, 최대 랭크는 한 겹 더 밝아집니다.

### L-4. 생활 숙련 — 같은 팝업의 다른 갈래

"능력과 특성" 팝업 위쪽에 갈래 둘이 생겼습니다 — **특성 트리 / 생활 숙련**.

숙련은 포인트로 찍는 것이 **아닙니다**. 밭에서 거두면 농사가, 물에서 올리면 낚시가
오릅니다(10레벨이 끝, 1->10 에 507). 그래서 화면에 누를 것이 없고, 지금 어디까지
왔는지와 다음에 무엇이 열리는지만 보여 줍니다.

| | 레벨마다 붙는 것 | 3 | 6 | 10 |
|---|---|---|---|---|
| **농사** | 성장 속도 +7% · 수확량 증가 확률 +5% · 씨앗 회수 +4% | 고른 씨앗 (씨앗을 반드시 하나 이상) | 두 손 가득 (25%로 두 배) | 풍요의 손 (거둔 자리에 저절로 다시 심긴다) |
| **낚시** | 입질 대기 -4% · 상위 어종 +2% · 잡것 +1.5% | 가벼운 손목 (챌 시간 1.0->1.6초) | 깊은 눈 (심해어 2.2배) | 물때를 안다 (25%로 한 마리 더) |

레벨이 오르면 그 자리에서 고리가 퍼지고, **특전이 열리는 레벨(3·6·10)** 에서는
챕터 카드로 무엇이 열렸는지 이름을 붙여 줍니다. 숫자만 오르면 오른 줄을 모릅니다.

닿는 자리는 넷뿐입니다.
`world.growCrops(rng, dayF, speed)` 에 배율 인자가 하나 늘었고(기본 1 — 안 넘기면 예전 그대로),
`game.harvestBonus()` 가 새로 생겨 다 여문 칸을 거둘 때만 불립니다(예전 동작이 1레벨의

### ★ `?v=` 는 이제 손으로 올리지 않습니다

183 -> 184 -> 185 로 세 번 손으로 올렸는데, 그러고도 **고친 것이 반영되지 않는 일이
또 났습니다**. 번호를 올리는 것만으로는 끝나지 않는 이유가 둘 있었습니다.

1. **번호를 들고 있는 파일이 `index.html` 자신입니다.** 브라우저가 `index.html` 을
   캐시에 물고 있으면, 번호를 올렸다는 사실 자체가 전달되지 않습니다. 옛 HTML 이
   옛 `?v=` 를 부르고, 그 URL 은 이미 캐시에 있으니 끝까지 옛 코드가 돕니다.
   `vercel.json` 에는 `/play/*.js` 를 한 시간 잡아 두는 규칙만 있었고, **HTML 을
   어떻게 다룰지는 아무 말이 없었습니다.**
2. **손이 빠지면 그만입니다.** 올리는 것을 잊은 배포는 그대로 옛 코드로 돕니다.

그래서 손을 뗐습니다.

- `tools/build-site.sh` 가 배포 때마다 **커밋 해시로 `?v=` 를 찍습니다**
  (`VERCEL_GIT_COMMIT_SHA` -> `GITHUB_SHA` -> `git rev-parse` -> 시각). 배포마다
  URL 이 통째로 달라지므로 옛것이 나올 길이 없습니다. `assets/sprites.js` 는 제
  `<script>` 태그의 물음표 뒤를 그대로 물려받아 그림 URL 에도 붙이므로
  (`_ver`), 스크립트·CSS·그림이 한 줄로 같이 따라옵니다.
  찍히지 않은 자리가 남으면 **빌드를 실패시킵니다** — 안 찍힌 판이 1년 캐시되는
  것이 제일 나쁩니다.
- `vercel.json` 을 다시 썼습니다. **html 은 매번 확인**(`max-age=0, must-revalidate`),
  js·css·그림은 **1년 immutable**(URL 이 배포마다 다르니 안전합니다),
  `manifest.json` 과 `version.json` 은 예외입니다. 규칙끼리 겹치면 어느 쪽이 이기는지가
  플랫폼 사정에 달리게 되므로, 소스 패턴을 **서로 겹치지 않게** 갈라 두었습니다.
- `game/index.html` 에 **자가 점검**을 넣었습니다. 그래도 옛 HTML 이 오면, 서버에
  `version.json` 을 물어보고 제가 든 판과 다르면 주소 뒤에 `?b=<판>` 을 붙여 **딱 한 번**
  새로 받습니다. 같은 판으로 두 번 시도하지 않게 세션에 적어 둡니다(무한 새로고침 금지).
  `file://`(zip)에서는 물어볼 데가 없으므로 건너뜁니다.

실측: 같은 판이면 아무 일도 없고, 옛 HTML 이면 `?b=` 로 한 번 이동하고, 그래도 옛
HTML 이 오면 더는 움직이지 않습니다. 그림 URL 은 `char/player.png?v=<커밋>` 로 나갑니다.

`game/` 을 직접 열어 보는 개발 중에는 `?v=185` 가 그대로입니다(찍는 것은 배포 때뿐).
그때는 예전처럼 강제 새로고침으로 보시면 됩니다.
