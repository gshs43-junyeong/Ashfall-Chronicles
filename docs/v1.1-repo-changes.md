## A. 시작 캐릭터 · 난이도 · 비석 · 설정

### A-1. 새로 생긴 데이터 (`js/data.js`)

| 이름 | 내용 |
|---|---|
| `CHARACTERS` | 시작 캐릭터 5종 — `id n tint story d base weapon bag (gold)` |
| `CHAR_OF(id)` | 못 찾으면 첫 번째를 돌려준다 (저장이 깨져도 안전) |
| `MODES` | `normal`(x1) · `hard`(x2 + 인벤토리 절반 떨굼) · `impossible`(x5 + 슬롯 삭제) |
| `MODE_OF(id)` | 위와 같음 |
| `KEY_ACTIONS` | 조작키 재설정 대상 14개 |
| `NOTICE_KINDS` | 알림 종류 4가지 (`bad` 는 항상 뜬다 — 끌 수 없음) |
| `SET_DEFAULT` | `view keys notice` 세 항목이 늘었다 |

### A-2. 게임 쪽 (`js/game.js`)

- `newGame(seedStr, slot, name, charId, mode)` / `_newGame(seed, name, charId, mode)`
  — **인자가 늘었습니다.** v1.1이 `newGame` 을 부르는 곳이 있으면 인자 수를 맞추세요.
- `modeMul()` → 난이도 배수. `Enemy` 생성자에서 `maxHp` · `dmg` 에만 곱합니다
  (경험치·금화는 안 건드립니다 — `scale()` 에 넣으면 보상까지 곱해집니다).
- `onDeath()` 가 난이도별로 갈립니다. `deathMark` 는
  `{ x, y, gold, xp, items, at }` 이고 `at = dayCount*1440 + dayT`,
  게임 내 12시간(720분)이 지나면 사라집니다. 거리 70 안에서 절반을 돌려받습니다.
- `resize()` — `this.W` / `this.H` 가 **화면 픽셀이 아니라 월드 좌표 크기**가 됐습니다
  (`innerWidth / z`). 배율은 `setTransform(dpr*z, …)` 에 들어갑니다.
  미니맵은 제 `MW/MH` 를 쓰므로 영향이 없습니다.
  **v1.1이 `this.W`/`this.H` 를 화면 픽셀로 쓰고 있으면 그쪽을 고쳐야 합니다.**
- `readInput()` — `I.wx = I.mx / z + this.cam.x` (배율 반영)
- `keysFor(id)` · `held(id)` · `isKey(id, code)` — 조작키 재설정용. 키 입력을
  `e.code === 'KeyX'` 로 직접 비교하던 곳은 `isKey('...', e.code)` 로 바꿔야 합니다.
- `toast(m, k)` 가 `settings.notice` 로 걸러집니다 (`'bad'` 는 항상 통과).
- `showNewGameForm(slot)` — 캐릭터·난이도 선택 UI가 들어갔습니다.

### A-3. 그 외

- `js/entity.js` — `Player.base = { str: 5, dex: 5, int: 5, vit: 5 }`,
  `Enemy` 생성자에 난이도 배수.
- `js/ui.js` — `buildNotices()` · `buildKeys()` · `captureKey(code)` 추가.
  `G.settings` 를 읽는 곳은 전부 `(G.settings && …) || {}` 로 감쌌습니다
  (`bindSettings()` 가 `loadSettings()` 보다 먼저 돕니다).
- `index.html` — 설정에 `#set-view` · `#set-notices` · `#set-keys` · `#set-keys-reset`.
- `css/style.css` — `.nf-*` · `.set-sub` · `.set-note` · `.set-row.key` · `.keybtn` ·
  `#death-screen.wipe #btn-respawn{display:none}`.

## B. 캐릭터 5종의 전용 시트

### B-1. 무엇이 바뀌었나

전에는 다섯이 `char/player.png` 한 장을 같이 쓰고 `source-atop` 색조로만 갈렸습니다.
이제 **다섯이 각자 제 시트**를 씁니다.

```
game/assets/char/player_wanderer.png
game/assets/char/player_digger.png
game/assets/char/player_ranger.png
game/assets/char/player_adept.png
game/assets/char/player_stray.png
```

- 각 1040x160 (20x40 논리픽셀 x 4배, 13프레임, 간격 0) — **원본 `player.png` 와 규격이 같습니다.**
- **프레임 순서도 원본과 완전히 동일합니다.**
  `idle1 idle2 walk1 walk2 walk3 walk4 jump fall dash atk1 atk2 atk3 hurt`
  → `playerFrame()` 을 그대로 씁니다. 새 시트를 그릴 때도 이 순서를 지키세요.
- `assets/manifest.json` 의 `characters.sheets` 에 다섯이 등록돼 있습니다.
  `Sprites.ready()` 가 자동으로 읽고 `footInset` 도 재 줍니다.
- `char/player.png` 는 **지우지 마세요.** 시트를 못 읽었을 때의 폴백 경로와
  `tools/mkchars.py` 의 입력으로 계속 씁니다.

### B-2. `drawPlayer()` (`js/game.js`)

```js
const ch = CHAR_OF(p.charId);
const fr = this.playerFrame(p);
if (this.spritesOn && Sprites.draw(c, 'player_' + ch.id, fr, sx, sy, p.facing < 0)) { … }
// 못 읽으면 옛 경로: 'player' 한 장 + ch.tint 색조
```

`CHARACTERS[].tint` 는 **지우지 마세요** — 폴백 색조 겸 선택 화면의 표식입니다.

### B-3. 시트를 다시 굽는 법

```
python3 tools/mkchars.py        # PIL 필요
```

`player.png` 의 픽셀을 부위(머리 / 피부 / 외투 / 바지 / 가죽 / 목도리 / 허리띠 / 외곽선)로
가른 뒤, 캐릭터별 색표로 갈아끼우고 실루엣을 조금씩 고쳐 다섯 장을 굽습니다.
머리카락과 바지가 원본에서 **같은 남색**이라 목도리 윗줄을 기준으로 위/아래를 갈랐습니다.
12번(피격) 프레임은 통째로 붉게 씻겨 있어서, 씻긴 걸 걷어내고 색을 바꾼 뒤 다시 씌웁니다.

캐릭터별 실루엣 손질:

| 캐릭터 | 색 | 실루엣 |
|---|---|---|
| 떠돌이 | 원본 그대로 | 가슴 멜빵, 허리 주머니 |
| 굴 파는 이 | 갈색 가죽 · 황토 작업복 | 챙 달린 안전모 + 이마 램프 |
| 사냥꾼 | 짙은 초록 | 뒤로 흘러내린 두건 자락, 등의 화살통 |
| 수련생 | 은발 · 보라 로브 | 긴 머리, 다리를 덮는 로브 자락 |
| 빈손 | 잿빛 | 헝클어진 머리, 톱니처럼 뜯긴 밑단, 맨발 |

색이나 실루엣만 바꾸고 싶으면 `tools/mkchars.py` 의 `CHARS` 표와 `op_*` 함수만 고치면 됩니다.

### B-4. 스토리

`CHARACTERS[].story` 가 늘었습니다. 새 게임 화면에서 선택한 캐릭터의 시트 첫 프레임과
함께 뜹니다 (`#nf-por` · `#nf-cstory`, css `.nf-card` / `.nf-por` / `.nf-story`).

## C. 타이틀 재구성과 활 겨눔

### C-1. 타이틀에는 버튼 넷만

`싱글플레이 · 설정 · 크레딧 · 나가기`. 저장 슬롯과 캐릭터 선택은 팝업으로 뺐고,
`조작법`(옛 `#help-box`)은 설정 안 `조작키` 아래로 합쳤습니다.

| 없어진 것 | 대신 |
|---|---|
| `#help-box` · `#btn-help` · `#btn-help-close` | 설정 안 `조작법` 절 (`.set-help`) |
| 타이틀 안의 `#slot-list` | `#slots-screen` 팝업 안으로 이동 |
| 빈 슬롯 카드를 폼으로 바꾸던 방식 | `#newgame-screen` 팝업 (`#newgame-box`) |
| `.nf-*` css · `.slot-form*` css · `.ts-menu2` | `.ng-*` css · `.modal` / `.modal-box` |

새로 생긴 것: `#slots-screen` `#newgame-screen` `#credits-screen` `#bye-screen`,
`G.openModal/closeModal/closeTopModal/closeAllModals/quit`, `G.MODAL_STACK`.
타이틀에서 **Esc** 는 열려 있는 팝업을 한 겹씩 닫습니다.
`나가기` 는 `window.close()` 를 시도하고, 브라우저가 막으면 작별 화면을 띄웁니다.

`SET_DEFAULT`(game.js)에 `view` · `keys` · `notice` 가 빠져 있어 설정의 시야 범위가
`undefined%` 로 뜨던 것을 고쳤고, 조작키 이름표의 화살표 표기(`←↑→↓ Left`)를 바로잡았습니다.

### C-2. 활은 겨눈 쪽을 향한다

`wc === 'ranged'` 무기(활·쇠뇌·총)는 `drawHeldWeapon` 에서 자루 무기용 90° 보정을 쓰지 않고,
겨눔 각도(`G.aimAngle(p)` — `doAttack` 이 쓰는 각도와 같다)만큼 돌려 그립니다.
아이콘이 이미 오른쪽(+x)을 쏘는 그림이라 각도만 맞추면 됩니다.

`BOW_HAND`(18) · `BOW_TIP`(= BOW_HAND + 11.4) 은 `js/data.js` 에 있습니다.
그리는 쪽(game.js)과 쏘는 쪽(entity.js `fireProj(..., BOW_TIP)`)이 같은 값을 봐야
화살이 활 끝에서 나가는 것처럼 보입니다 — **한쪽만 고치지 마세요.**
`fireProj` 는 몸에서 활 끝까지를 반 칸 간격으로 훑어, 막힌 데가 있으면 거기서 화살을 냅니다
(벽에 붙어 쏠 때 화살이 벽을 건너뛰지 않게).
