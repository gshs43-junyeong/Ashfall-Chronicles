# v1.1.2 멀티플레이 설계

계획서 `docs/v1.1.1-engine-plan.md` §9-2 1번. 구조를 먼저 정하고(이 문서) 단계별로 만든다.

## 1. 사용자 결정 (2026-10-01)

| 항목 | 결정 |
|---|---|
| 연결 | **브라우저끼리 직접(WebRTC P2P)** — 호스트의 게임이 서버 노릇. 상시 게임 서버 없음 |
| 인원 | **2~4명** |
| 진행 | **세계는 공유, 캐릭터는 각자** — 장·마을 단계·유적 기록·보스 처치는 호스트 세계 것, 레벨·가방·스킬·펫은 플레이어마다. 참가자는 제 캐릭터를 들고 남의 세계에 들어갔다 나온다 |
| PvP | **호스트가 설정에서 켜고 끈다**(기본 끔) |
| 채팅 | 멀티플레이에서만. **호스트가 켜고 끈다**(기본 켬) |

## 2. 지금 구조와 부딪히는 곳 (2026-10-01 실측)

| 항목 | 실측 | 결론 |
|---|---|---|
| `G.player` 참조 | 27개 파일 263곳 | 플레이어 하나 가정 — `G.players[]` + `G.me`(이 화면의 플레이어)로 가른다(M0) |

| 세계 전체가 도는 것 | 공장(`Factory.tick`) · 작물 · 날씨 · 시계 · 운석 | 호스트만 돌리고 결과를 보낸다 |
| 세이브 | 세계 + 플레이어(`p`) + 진행이 한 덩어리 | **캐릭터 저장**과 **세계 저장**을 가른다(세이브 v13 — `SAVE_UPGRADES` 한 칸) |
| 사이트 | Vercel 정적 | 연결 중개(시그널링)만 아주 작게 둔다(§4) |

## 3. 구조

```
 호스트 브라우저                         참가자 브라우저 (최대 3)
 ┌───────────────────────────┐          ┌───────────────────────────┐
 │ G (권위)                   │  입력 ←──│ G (그림 + 제 캐릭터 예측)   │
 │  world · 몹 · 공장 · 시계   │          │  world 사본 · 몹 그림자      │
 │  players[0..3]             │──→ 상태  │  players[] (나 = me)        │
 │  net.host (DataChannel×n)  │  변경분  │  net.client (DataChannel)  │
 └───────────────────────────┘          └───────────────────────────┘
```

- **호스트 권위**: 몹 AI · 피해 판정 · 떨어진 물건 · 상자 · 기계 · 작물 · 날씨 · 시계 · 운석 · 장 진행은 호스트만 계산한다.
- **참가자 예측**: 제 캐릭터 이동·점프·헤엄은 바로 움직이고(같은 `Player.move`), 호스트가 보낸 위치와 많이 어긋나면 당겨 맞춘다.
  공격·채굴·놓기는 **요청**을 보내고 호스트가 판정한 결과(타일 변경 · 피해 숫자 · 물건)를 받는다.
- **다른 플레이어·몹**: 호스트가 초당 15번 보내는 위치를 100ms 늦춰 두 장 사이를 보간해 그린다.
- **타일**: 호스트의 `world.set` 이 바뀐 칸을 모아 틱마다 보낸다. 참가자 쪽은 받은 칸을 `set` 으로 넣는다(빛·미니맵·물이 그대로 따라온다).
- 참가자가 끊기면 그 캐릭터는 세계에서 빠지고 참가자 브라우저에 저장된다. **호스트가 끊기면 판이 끝난다**(호스트 이전은 안 한다).

### 3-1. 무엇이 누구 것인가

| 플레이어마다(캐릭터 저장) | 세계(호스트 세계 저장) |
|---|---|
| 레벨·경험치·능력치·스킬·특성 · 가방·장비·금화 · 펫·드래곤 · 숙련도 · 업적 · 통계(kills·mined·deepest…) · 보관고 | 타일·벽·기계·작물·물 · 장(`chapter`)·이야기 기록·마을 단계·상점 재고·현상금 · 유적 탐사 기록·둥지·메아리 · 시계·날씨·날짜 · 지도 탐험 기록(플레이어마다 따로 — 남이 가 본 곳은 안 밝혀짐) |

- **장 목표**(죽이기·캐기·깊이 등)는 그 세계에 있는 플레이어 **누구든** 채우면 된다(세계 기록으로 센다). 장 보상(경험치·물건)은 **그 자리에 있는 모두**가 받는다.
- 업적은 캐릭터 것 — 혼자 할 때와 같다.
- 보관고는 캐릭터 것(어느 세계의 마을에서 열어도 제 보관고).

### 3-2. 밸런스(초안 — M5 에서 실측으로 고친다)

- 몹 생성: 플레이어마다 제 주변에서 따로 굴리되 세계 전체 상한은 인원 × 0.75.
- 보스 체력 × (1 + 0.6 × (인원 − 1)) · 보상은 각자 굴림.
- 경험치: 처치 경험치는 반경 안 플레이어 모두에게 그대로(나누지 않는다 — 함께 하는 것이 손해가 아니게).
- 떨어진 물건은 줍는 사람 것, 상자는 처음 연 사람 것(테라리아식). 금화 줍기는 각자.
- 시간은 멈추지 않는다 — ESC 창·가방을 열어도 세계는 돈다(혼자 할 때만 멈춘다).

## 4. 연결

1. 호스트가 "세계 열기" → 4글자 **방 코드**.
2. 참가자가 코드 입력 → 중개를 거쳐 WebRTC offer/answer 교환 → DataChannel 두 개(순서 보장 `rel` · 비순서 `fast`).
3. 참가자 → `hello`(판 · 캐릭터 요약) → 호스트가 판·세계 크기 확인 후 **세이브 스냅샷**(gzip, 소형 약 200 KB 예상)을 조각으로 보냄 → 참가자가 세계를 열고 `ready`.

**중개(시그널링)**: Vercel 함수 하나(`/api/room`) + 작은 저장소(Upstash Redis — 무료 범위)에 방 코드 → offer/answer 를 몇 초 맡겨 둔다(짧은 폴링, 소켓 없음).
zip(file://)·Electron 도 같은 주소로 붙는다(CORS 허용).
**TURN**(엄격한 NAT 뒤라 직접 못 붙는 경우, 보통 10~20%): 처음엔 STUN 만 → 실패하면 "연결할 수 없다" 안내. TURN 은 실측 실패율을 보고 정한다(유료가 될 수 있어 따로 확인).

## 5. 메시지

엔진 `src/engine/net`(게임을 모른다) — 전송 틀(`Transport`: WebRTC · 같은 탭 시험용 loopback) · 조각 나누기/잇기 · 보간 버퍼.
게임 `src/game/net/*.ts` — 메시지 종류와 적용.

| 방향 | 이름 | 채널 | 내용 |
|---|---|---|---|
| 참가자→호스트 | `in` | fast | 입력 비트·조준 · 순번(초당 30) |
| | `act` | rel | 캐기·놓기·공격·상호작용·제작·가방 이동 요청 |
| | `chat` | rel | 글(200자 · 호스트가 끄면 막힘) |
| 호스트→참가자 | `snap` | fast | 플레이어·몹·투사체 위치/상태(초당 15, 화면 근처만) |
| | `tiles` | rel | 바뀐 칸 [i, 타일, 벽](틱마다 모아서) |
| | `ev` | rel | 피해 숫자·효과·소리·알림·장 진행·드롭 생성/줍기 |
| | `mach` | rel | 기계 상태 변경(공장 창이 열린 기계는 자주) |
| | `cfg` | rel | PvP·채팅 켜짐 · 시계·날씨 |

## 6. 단계

| 단계 | 내용 | 확인 |
|---|---|---|
| **M0 구조** | `G` 를 인스턴스로(계획서 2단계 ④) · `G.player` → `G.me` / `G.players` 로 가르기(263곳을 "이 화면의 플레이어"와 "어느 플레이어든"으로 분류) · 세이브를 캐릭터/세계로 가르기(v13) | 혼자 하기가 바이트 단위로 같다(`npm run check` · 세이브 대조) |
| **M1 엔진 net** | `src/engine/net` — Transport · loopback · WebRTC · 조각 · 보간 · 시험(`npm run test:net`) | 같은 탭 두 끝 · 헤드리스 크롬 두 페이지 |
| **M2 붙기** | 방 코드 · 중개 함수 · 스냅샷 전송 · 참가자 세계 열기 · 다른 플레이어 그리기 · 걷기 동기화 | 두 페이지에서 서로 걷는 모습 스크린샷 |
| **M3 세계 동기화** | 타일 변경 · 채굴/놓기 요청 · 몹·투사체·피해 · 드롭·상자 · 기계 · 시계·날씨 | 시험: 참가자가 캔 칸이 호스트에, 호스트 공장 물건이 참가자에 |
| **M4 UI** | 세계 열기/참가 창 · 이름표 · 파티 목록·핑 · 채팅(호스트 토글) · PvP 토글 · 내쫓기 · 끊김 처리 · 6개 언어 번역 | 6개 언어 화면 검사 |
| **M5 밸런스·마무리** | 몹·보스 배율 실측 · 장 진행 공유 · 펫 · 죽음·부활 · 문서 | 2~4인 실제 플레이 |

M0 는 혼자 하기에도 들어가는 '옮기는 커밋'이고, M1 부터 '바꾸는 커밋'이다. 멀티플레이 기능은 M4 까지 설정 뒤에 숨겨(`?mp=1`) 웹 개발판에서만 연다.

## 7. 안 하는 것(이번 판)

호스트 이전 · 전용 서버 · 4명 넘게 · 음성 · 세계 안 플레이어 상점 거래 · 치트 방지(참가자 캐릭터는 참가자 브라우저에 있으므로 고칠 수 있다 — 테라리아와 같다. 호스트는 내쫓을 수 있다).

## 8. 열린 것

- TURN 서버 여부(M2 실측 뒤).
- 중개 저장소: Upstash 무료 범위로 충분한지(방 하나 = 몇 KB · 10분 만료).
- 참가자가 다른 판(v1.1.2 dev ↔ 다른 커밋)일 때 — 번들 해시가 같아야만 붙게 한다(어긋나면 "판이 다르다").
